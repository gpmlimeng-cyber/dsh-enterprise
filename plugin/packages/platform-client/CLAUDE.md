成员清单

README.md: 平台客户端使用与安全边界，记录可选安装默认值、官方 settings 地址持久化、本地 API 和 Token 不出 Host 约束。
package.json: 私有 workspace package 清单，声明 caret-compatible Cordis/credentials/settings/Schemastery peers、T02 contracts 与 strict Zod 运行依赖。
tsconfig.json: Host TypeScript 构建边界，从 `src/` 生成 ESM、声明与 sourcemap 到 `lib/`。
src/branding.ts: 企业品牌 Host 侧边界——免登录 `GET /enterprise/api/v1/branding` 取数（短超时 3s）、revision 去重的磁盘缓存 `$DSH_HOME/enterprise/branding.json` 加位图副本目录、以及「位图 MIME 白名单 / 512KB 尺寸上限 / 只收平台同源地址」三道资源门禁；LOGO 槽位按契约真源同时接受裸字符串与 `{ url, sha256, … }` 对象（只取 `url`，其余字段与未知字段一律忽略，实际字节仍以响应 MIME 头与下载长度为准），同 revision 只补缺失副本且待补槽位取自本次远端声明（旧版 Host 把对象形 LOGO 读成 null 的空副本缓存因此自愈）、绝不覆盖文档字段，一切失败（不存在/未配置/离线/解析失败/超时/资源非法）都降级为「没有企业品牌」并只留一条 warn，内置默认由 ui 侧持有。
src/browser.ts: 通过无 shell argv 调用系统 URL opener，向 PKCE 事务提供可取消的**桌面**浏览器交接；只认 darwin/win32/linux——安卓上宿主没有任何可用的开源路径（Termux 与系统的 `am` 都会被 `ActivityTaskManagerService.assertPackageMatchesCallerUid` 以「包名不属于调用 uid」拒绝），那条路改由 `browserHandoff: 'client'` 交给浏览器半。
src/callback-page.ts: 回环结果页的唯一渲染器——`pickCallbackLocale` 按 `Accept-Language` 首选语言（q 值优先、同 q 先出现者胜、`q=0` 视为不偏好）决定中/英文，**缺省中文**：缺失、空、畸形、通配与无法解析，以及 fr/de 等既非 `zh` 又非明确 `en` 的偏好，一律回落导出的 `CALLBACK_DEFAULT_LOCALE`（`zh`，产品要求缺省中文），只有 best q 的主子标签明确是 `en` 才用英文；`escapeHtmlText` 是品牌与企业欢迎语进入 HTML 的唯一转义出口（名称→简称→欢迎语→内置 `DSH Enterprise` 逐级回落），`renderCallbackPage` 产出 `<!doctype html>` 单文件页：内联样式、`color-scheme` + `prefers-color-scheme` 深色、无任何外链/CDN、成功态尽力 `window.close()` 一次并保留按钮与手关闭提示、失败态只给结论与「请回到客户端重试」而不回显原始错误。
src/index.ts: package 公开入口，集中导出 Service、PKCE 与回环结果页、installation、bootstrap、品牌缓存、本地 API 契约（含企业技能**四条**同源路由的路径常量 `/skills/{install,uninstall,installed,content}` 与 `skillAction`/`skillStatus`/`skillContent` 端口形状，以及**配方一键启用三端口 `presetEnable`/`presetDisable`/`presetStatus`**）与地址写入诊断串。
src/installation.ts: 统一解析 DSH_HOME 并原子维护 `enterprise/device.json`，严格限定 UUID v4、显示名和创建时间；原子创建优先 `link(tmp→path)`（桌面/Linux），遇文件系统拒硬链接（Android/FUSE EACCES 等）回退 `writeFile(path, wx)`——两者同 O_EXCL 竞态语义，不覆盖并发者已写文件，使拒硬链接的文件系统上仍保并发安全。
src/local-api.ts: exact/prefix 同源路由暴露企业目录、严格 package/version 安装与 package 卸载动作、**四条企业技能路由：三条 exact 动作（`/skills/install`、`/skills/uninstall`、`/skills/installed`，单键 `{packageId}` 雪花朵入参、动作后回传最新已装态、`ENT_SKILL_NAME_CONFLICT` 投影 409）与一条 exact 只读正文（`GET /skills/content?packageId=…&name=…`，查询键集必须**恰好**是这两个标识符、包 id 雪花 / 技能名官方 kebab，多给少给重复一律本地 400 且**不进端口**；名字只当「本包已装记录里的键」转交，路由层不拼任何路径——路径安全在 bundle 侧；`ENT_SKILL_CONTENT_TOO_LARGE`→413、`ENT_SKILL_CONTENT_INVALID`→409、`ENT_RESOURCE_NOT_FOUND`→404）**、只读品牌文档与品牌位图副本，以及 Server/账号/Session JSON 与显式刷新（品牌读取恒 200，缺品牌回 `data: null` 由 ui 回落内置）；**三条详情 prefix（`/branding/asset`、`/sessions`、`/presets`）的注册 path 与各自父路径逐字相同、不带尾斜杠**——引擎 `dsh-host-webserver` 的 `match()` 只做「路径段前缀」（`pathname === prefix || pathname.startsWith(prefix + '/')`，exact 表整路径优先、prefix 表取最长），带尾斜杠会让 `/branding/asset/<slot>`、`/sessions/<id>/copies`、`/presets/<id>` 在引擎层就是空体 404（handler 根本不进），而 handler 内 `slice()` 用的仍是含斜杠的边界串（`${...}/` 与注册 path 不是同一条串）；exact 与 prefix 是引擎里的两张表，故 `/sessions`、`/presets` 上「列表 exact + 详情 prefix」共用同一字符串不冲突，`/sessions/sync` 这条 sibling exact 也仍被 exact 表优先命中；执行端口由 bundle 反向注入以避免依赖环，`onError` 只上报操作名/原始 error/最终状态码而不改响应语义；另对外导出**稳定码 → HTTP 状态的唯一映射** `enterpriseLocalErrorStatus`（原私有 `actionErrorStatus`，行为逐字不变）——bundle 侧两条本机技能文件子路由 `/skills/<id>/files`、`/skills/<id>/file` 必须与本文件的 `/skills/content` 共用这张表，否则同一种失败会在同族路由上给出两个状态码。 **本刀（调用面补记）**：导出给 bundle 的 `enterpriseLocalErrorStatus`（稳定码 → HTTP 状态的唯一映射）现在同时服务三条只读技能路由——本文件的 `/skills/content` 两条只读入口（`/skills/<id>/files`、`/skills/<id>/file`）由 bundle 那侧共用；对应地，`packages/ui` 的同源客户端新增 `skillFiles` / `skillFile` 两条取数（路径 `/skills/<id>/files` 与 `/skills/<id>/file?path=`；本文件的服务端注册面与形状一字未改）。 **宿主接线刀（配方一键启用）**：同一条 `/presets` prefix 再按**后缀**分派三条新子路径 `POST <id>/enable`（`id` 雪花；请求体是**关闭键集**——`{}` 或恰好 `{confirmFingerprint}`，未知键/类型不对一律本地 400 且不进端口）、`POST <id>/disable`（`id` 是 kebab 声明 id，请求体必须空对象）、`GET <id>/status`（`id` 雪花）；三条都**不新增注册字符串**——引擎 `register()` 对同 kind 同 path 抛 `duplicate prefix route`（启动即崩）、exact 表表达不了动态 `<id>`，故形状与 bundle 侧 `/skills` prefix 分派本机文件子路径同款；端口缺席（组合层未接线）一律 400，失败经 `onError` 留痕；`enterpriseLocalErrorStatus` 同时补上配方启用的码族（`ENT_PRESET_RECIPE_INVALID`→400、`ENT_PRESET_AUTHORIZATION_REQUIRED`→403、`ENT_PRESET_{AUTHORIZATION_STALE,INSTALL_IN_PROGRESS,INSTALL_CANCELLED,STATE_INVALID}`→409、`ENT_PRESET_{INSTALL_FAILED,UNINSTALL_FAILED,BUNDLE_WRITE_FAILED,ARTIFACT_UNAVAILABLE}`→503）。
src/pkce.ts: PKCE S256 生成、仅绑定 `127.0.0.1` 的 callback、state/取消/超时生命周期，并把浏览器可见结论交给 callback-page：语言在回调入口只判定一次，可选 `branding` 端口只读已缓存品牌（缺省/抛错回落内置名），成功、state 失配、缺 code、`error=` 回调与超时后的迟到回调各自渲染对应结果页；另有可选 `onCallbackRequest` 诊断端口，把截断到 `ACCEPT_LANGUAGE_LOG_LIMIT`（200）的 `Accept-Language` 原文与判定结论交给组合层，端口在响应刷出后才释放，避免用户只看到 connection reset。
src/platform-credentials.ts: 独占官方 GrantRecord 与内存 Access Token，在 credentials 原子修改边界内轮换 Refresh Token，并阻止过期 origin 或已销毁 Service 重新装载认证态。
src/platform-service.ts: 注册 `ctx.enterprisePlatform`，并把组合层注入的 `pluginStatus`/`pluginAction`、`skillStatus`/`skillAction` 与**只读正文 `skillContent`**、以及**配方一键启用三端口 `presetEnable`/`presetDisable`/`presetStatus`** 原样转交 `registerEnterpriseLocalApi`（技能动作端口缺席即不注册那三条动作路由、正文端口缺席即不注册 `/skills/content`、配方三端口缺席则 `/presets/<id>/{enable,disable,status}` 如实按非法请求拒），把 Server 地址收敛到官方 rc.2 settings 中 owner profile entry 的 volatile Config 引用（命名空间即 entry id，写入经 `settings.update`，官方 Settings 不生成页面），保存期间禁止登录；写回判定只看**本次写入的新值**，空串按「未设置」跳过（首次配置不得被当成非法旧值抹掉），连接态或非法的外部改址写回最近一次被接受的有效地址，不可持久化时报 `ENT_SETTINGS_UNAVAILABLE`，且五个不可持久化判定点（entry id 缺失 / volatile 引用缺失 / `configure` 抛错 / 写入端口未装配 / `settings.update` 抛错）都在抛错前经 Host logger 留下 operation、地址、entryId、entry 可见性与原始 error；编排登出、启动恢复、按需续期/401 单次重放、会话代次隔离与显式 bootstrap 刷新，并在构造、登录成功与 Server 切换三个时点各拉一次品牌（不轮询、不常驻 SSE）。`browserHandoff: 'client'`（安卓）时宿主不碰浏览器：自己 `GET` 授权 URL（不跟随重定向）取 `transaction_id`、再取 `/sources`，把授权 URL 挂到 AUTHORIZING 状态下发作为「走原生表单」的信号，账号密码与改密由界面经本机路由代收（凭证只在内存中构造成 multipart 转发，不落盘不进日志），成功后自己跟随回环回调（只接受以本事务回调为前缀的地址）；`host`（默认）保持宿主直接打开且状态下永不带该字段。
src/settings-diagnostics.ts: 地址写入诊断层，按结构只读官方 `configEditor.entries()`（含全局 id/name/runtime/ACTIVE/configKeys/schema 与 volatile 字段名）与 settings 的能力位，并给出异常 name/message/code/stack 摘要；刻意不调用会广播 `settings/document-updated` 的官方 `describe()`，保证探测零副作用。
src/types.ts: 复用生成契约严格校验含空签名制品的 Bootstrap、模型、配额与受管插件（插件分配含**可选位** `displayName`（员工端卡片**标题**；契约里是必填位，这里写 `.optional()` 只为旧服务端留兼容窗口——缺席由渲染层回退包名）与可选 `description`），定义公共 Service 配置（含官方 volatile Server 地址引用与 `settingsReference` 识别、`browserHandoff` 浏览器交接方）与组合层端口（`pluginStatus`/`pluginAction`/`skillStatus`/`skillAction`/**`skillContent`**/**`presetEnable`/`presetDisable`/`presetStatus`**（企业配方一键启用三条子路径；由 bundle 侧实现，缺席即如实按非法请求拒）/`uninstallPlugin`/`sessionSync`）、稳定错误及无秘密状态 DTO（含 client 交接窗口内的 `authorizeUrl`）。
