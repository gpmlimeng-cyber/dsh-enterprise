tryRegisterHostSessionSync 条件挂载会话同步，并以自定义地址串行热重挂官方账户插件（先释放旧实例再挂载，失败回滚）；同处注册三条同源路由：用量只读镜像、反馈 multipart 透传，以及**帮助中心出口**（`help-route.ts`，地址由 Host 按自己配置的平台地址加固定 `/help/` 派生后用 PKCE 那条系统浏览器通道打开，浏览器无法注入 src/account-origin.ts: 账户后台地址语义层 —— 企业默认域名、写入前的 origin 校验纯函数、串行幂等的 `AccountOrigin` 热重挂控制器，以及 `/enterprise/api/v1/local/account-origin` 的 GET/POST 同源路由（settings 不可写时投影 503 `ENT_SETTINGS_UNAVAILABLE`，并经 `report` 端口把操作名与原始 error 交给组合层 logger）；不感知 Cordis fiber。
src/models-status.ts: 企业模型挂载状态诊断 —— `GET /enterprise/api/v1/local/models/status` 只读投影 bootstrap 是否就位、模型数与协议、官方 pi-ai 行是否定位、已写入的 providers（含 enterprise 前缀过滤）；Host 日志不落盘时用它定位企业模型不显示的断点，非 GET 405、异常 503 且留判定点 warn。
src/usage-route.ts: 用量只读镜像 —— `GET /enterprise/api/v1/local/usage` 由 Host 代取中心 `/enterprise/api/v1/usage/me`（Access Token 不进浏览器），把上游 `{data, requestId}` 投影成本地单键 `{data}`；上游 401/会话过期投影 401、其余失败投影 503 并经 `onError` 留下操作名、判定点与原始 error，非 GET 一律 405 且不触发取数。
src/feedback-route.ts: 反馈 multipart 透传 —— `POST /enterprise/api/v1/local/feedback` 由 Host 代取 Access Token 转交中心 `/enterprise/api/v1/feedback`（令牌不进浏览器）；有界读取正文（三张满额附件 + 1 MiB 分帧余量）后重建提交体：`metadata` 保留浏览器字段但 **`diagnostics` 一律用 Host 采集值覆盖**（封闭五键 pluginVersion/hostVersion/os/installationId/lastErrorCode，逐字段按契约正则收窄，越界退化成 null），附件按**魔数**重写 content-type 并以新 boundary 分帧（文件名去危险字符）；本地先按中心同名口径限流（>3 张与非法位图→400 `ENT_FEEDBACK_ATTACHMENT_INVALID`、单张 >2 MiB 或正文超界→413 `ENT_FEEDBACK_ATTACHMENT_TOO_LARGE`）；`Idempotency-Key` 选填 UUID v4 原样透传、非法值本地 400；上游 401/`ENT_AUTH_REQUIRED`/`ENT_AUTH_SESSION_EXPIRED` 投影 401，中心三个稳定业务码按契约状态透传（400/400/413）且不留痕，其余失败投影 503 并经 `onError` 留下 operation/step/status 与原始 error，非 POST 一律 405 且不触发取数。
src/help-route.ts: 帮助中心出口 —— `POST /enterprise/api/v1/local/help/open` 无正文：地址由 `enterpriseHelpTarget(origin())` 从 Host 当前平台地址派生并拼固定 `/help/`（严格 allowlist = 没有可注入的输入，畸形/未配置/非 http(s) 一律 undefined），再用 `openSystemBrowser`（与 PKCE 登录同一条系统浏览器通道）打开；成功回 `{data:{opened:true}}`，平台地址不可用或交接失败投影 503 `ENT_PLATFORM_UNAVAILABLE` 并经 `onError` 留判定点与原始 error，非 POST 一律 405 且不交接；客户端在交接途中断开（响应未写完即 close）才中止，避免误杀自己的 execFile。
src/skill-errors.ts: 技能安装纵深唯一的失败码边界——封闭的 `EnterpriseSkillInstallErrorCode`（`ENT_INVALID_REQUEST`/`ENT_RESOURCE_NOT_FOUND`/`ENT_PLATFORM_UNAVAILABLE` + `ENT_SKILL_{DOWNLOAD_FAILED,SIZE_MISMATCH,HASH_MISMATCH,ARCHIVE_INVALID,PACKAGE_MISMATCH,NAME_CONFLICT,STATE_INVALID,INSTALL_FAILED}` + 只读正文那两条 `ENT_SKILL_CONTENT_{TOO_LARGE,INVALID}`；「本包没装」与「名字不在本包记录里」复用 `ENT_RESOURCE_NOT_FOUND`，不为同一种结果造第二枚码）、只携带稳定 code 的 `EnterpriseSkillInstallError` 与归一化函数 `skillInstallError`；错误里不放响应正文、宿主绝对路径或包内文件名，与 platform-client 导出的 `enterpriseLocalErrorStatus` 投影表一一对应（`ENT_SKILL_NAME_CONFLICT`→409、`ENT_SKILL_CONTENT_INVALID`→409、`ENT_SKILL_CONTENT_TOO_LARGE`→413，其余技能族→503；bundle 的两条本机技能文件子路由与本文件的 `/skills/content` 共用这张表）。
src/zip-archive.ts: **唯一**的 ZIP 解包内核（技能包 `.dshskill` 与配方包 `.dshpreset` 共用，绝不各自再写第二个解析器）——手写最小 ZIP 中央目录解析（EOCD 定位、CRC-32、store/deflate、显式拒绝 ZIP64/多盘/加密/未知压缩方法），解压**前**完成路径逃逸拒绝（绝对路径、盘符、反斜杠、空段、`..`、控制字符、超长段、重复路径、非 UTF-8 往返）与符号链接/设备/FIFO 拒绝，解压中执行调用方给的三条上限（压缩包字节 / 条目数 / 解压总量）；只交回逐条 `{path, isDirectory, bytes}`，错误一律 `ZipArchiveError`（不带业务码，由各布局层翻成自己的稳定码）。
src/skill-archive.ts: `.dshskill` 的**布局边界**（容器层门禁在 `zip-archive.ts`，本文件只保留技能布局判定）——调 `readZipEntries` 并把 `ZipArchiveError` 翻成 `ENT_SKILL_ARCHIVE_INVALID`（消息逐字保留），再执行 50 MiB 压缩包 / 200 MiB 解压总量 / 1 万条目 / 256 KiB 单 SKILL.md 上限；只认根 `manifest.json`（`format=dsh-skill` `version=1` + 合法 `id`）与 `skills/<kebab>/SKILL.md` 子树，不解析 frontmatter 正文语义（那是官方 `skill-filesystem` 的职责），也不执行包内任何内容。
src/preset-archive.ts: `.dshpreset` 的**布局边界**——在同一个 ZIP 内核之上做配方布局判定（根 `manifest.json` 必须 `format=dsh-preset` `version=1` + `PresetPresetId` 形状 `id` + `name ≤120` + 可选 `description ≤2000`/`order`；`preset/agent.cordis.yml`（缺省回落 `.yaml`）必须存在且是 ≤1 MiB 的非空 UTF-8 文本；**只允许根与 `preset/` 下路径**，`zip -r` 的父目录条目 `preset/` 忽略、其余 `preset/` 下文件不参与 composition），任何不合规都抛 `ENT_PRESET_RECIPE_INVALID`；**不解析 YAML 方言**（`!!js`/`cordis:group` 的语义权威是官方 Loader），产出核心可直接安装的 `PresetRecipe` + 包内 `presetId`。包内**可选**的 `preset/preset.yml` 按官方 `@deepseek-ai/dsh-agent-presets` 的显示元数据口径抄事实（`METADATA_FILE = "preset.yml"`、`renderPresetMetadata` 只写 name/description/order、`lib/index.js:30` "Every read failure degrades to no metadata"）→ `PresetRecipe.localMetadata`：只按名取 `name`/`description`/`order`/`id`，缩进块/未知键/坏值/读不成 mapping 一律降级为"没有元数据"，**绝不因此拒一份合法配方**（真机制品那份写的是 `version: 1` + `id:`，`version` 不是官方元数据键故忽略）。
src/preset-source.ts: 配方纵深的**配方正文来源**——一键启用必须读配方包里的 `preset/agent.cordis.yml`，而中心唯一能给它的就是**既有**运行时授权下载 operation（契约 `contracts/enterprise-openapi.yaml:152` → `contracts/paths/preset.yaml:189-221` `downloadRuntimePreset`；ui 侧现在自己拼同一个 URL 交给 Agent，见 `ui/src/preset-market.tsx:56-61`）：详情取权威 `versionId/sha256/sizeBytes` 走既有 `EnterprisePlatformService.getPreset`（与 platform-client `/presets/<id>` 本机路由同一份取数面），字节走**共用下载内核** `downloadVerifiedArtifact`（与技能安装同一个：size+SHA-256 强制校验、`.part` 原子改名、sha256 内容寻址缓存 ⇒ 同 sha256 再取零网络），落 `<dshHome>/enterprise/preset-artifacts/<sha256>.dshpreset` 后由 `preset-archive.ts` 解出配方。**不新造第二个下载通道**；上游受控码原样穿透，制品对不上（下载/大小/hash/包内 `presetId` 与详情不符）统一 `ENT_PRESET_ARTIFACT_UNAVAILABLE`。
src/preset-service.ts: 配方纵深的**宿主接线层 + 出 host 的脱敏闸门**（核心与本地路由之间那一段）——三条本机路由端口 `enable(presetPackageId, confirmFingerprint?)`/`disable(declarationId)`/`status(presetPackageId)`，把核心的**结果对象**投影成三个关闭键集的脱敏视图（`EnterprisePresetEnableView`/`EnterprisePresetDisableView`/`EnterprisePresetStatusView`：**绝不带** `bundleDir` 这类宿主绝对路径、`rowId` 与官方自由文本 `warnings`——后者只经 `onError` 留 Host 日志）并把失败一律翻成抛出的稳定 `EnterprisePresetError`（200 只回成功事实；唯一一处决定一次失败带哪枚码，因为 `platform-client` 的 `enterpriseLocalErrorStatus` 只认稳定码）；授权写入**只发生在**调用方交来 `confirmFingerprint` 且与当前配方指纹逐字相等时（把员工确认过的那份披露与指纹绑死，否则一律按核心三态拒），`status` 与 `enable` 复用同一次渲染因此看同一份指纹。
src/skill-install.ts: 技能纵深的**落盘所有者**——`installedSkillStatus`/`installSkillPackage`/`uninstallSkillPackage`/**`installedSkillContent`**（读一条已装技能的 SKILL.md 正文）/**`installedSkillFiles`**（列一条已装技能包在本机真树上的全部条目：路径/类型/字节数、码元升序确定性排序、一个包多个技能目录都从 `record.names` 起）/**`installedSkillFile`**（读一个**文本**文件，二进制按稳定码拒）与 `createEnterpriseSkillInstall`（`status`/`action`/**`content`/`files`/`file`** 五个端口）；**三个只读入口共用同一份路径实现**——`requireRelativeSkillPath` 是唯一的相对路径门禁（包 id 按雪花、首段按官方 kebab 且 ≤64、`..`/绝对路径/盘符/反斜杠/控制字符/空段/单点段/单段 >255/总长 >1024/**解码一次后仍出现 `%` 的二次编码绕过**一律在拼路径前即 `ENT_INVALID_REQUEST`），`resolveInstalledSkillTarget` 是唯一的落点解析（名字必须**命中本包自己的已装记录**——记录来自 Host 私有状态文件、读盘时已重新按 kebab 收窄；技能根与技能目录各自 `realpath` 且目录必须逐字等于 `<真实技能根>/<name>`；落点由 Host 自己拼，`lstat` 拒符号链接/非普通文件，`realpath` 规范化后必须逐字等于 `<真实技能目录>/<rest...>`；单文件复用包内 SKILL.md 的同一条 256 KiB 上限，`stat` 一次 + 读回后再按真实字节查一次），文本读取也只有一份（UTF-8 `fatal` 解码 + 拒夹 NUL 的二进制）；文件树另有三道收敛：条目数 `SKILL_FILE_MAX_ENTRIES`、嵌套深度 `SKILL_FILE_MAX_DEPTH`、任何符号链接或非常规条目一律 fail-closed；正文读取全程不碰网络，也不产生任何写副作用；顺序固定为「中心详情取权威 versionId/sha256/sizeBytes/技能名集合 → 代取令牌下载并强制校验 size+SHA-256（复用 plugin-distribution 的 `downloadVerifiedArtifact`）→ 解包 → 包契约与详情逐项对齐 → 落点冲突预检 → 解到 `<dshHome>/enterprise/skill-staging/<uuid>` → 逐个原子改名进官方 user-dsh 根 `<dshHome>/skills` → 原子写 `<dshHome>/enterprise/skill-installs/installed.json`」，任一步失败都撤回本次已改名的目录；同 sha256 幂等、状态文件损坏 fail-closed、卸载只删本包独占的技能目录；路径一律用 `resolveEnterpriseDshHome()`（与官方 `dsh-home-paths` 同一套优先级），因此落点正是官方 `dsh-skill-filesystem` 的 rank 400 根，watcher 深度 1 直发现（无需重启）。
src/skill-route.ts: 企业技能目录**只读取数**镜像 —— `GET /enterprise/api/v1/local/skills`（列表，exact）与 `/skills/{packageId}`（详情，prefix）由 Host 代取中心 runtime 面 `/enterprise/api/v1/skills[/{id}]`（Access Token 不进浏览器），把上游 `{data, requestId}` 投影成本地单键 `{data}`；**详情 prefix 注册成与列表逐字相同、不带尾斜杠的路径**——引擎 `dsh-host-webserver` 的 `match()` 只做「路径段前缀」（`pathname === prefix || pathname.startsWith(prefix + '/')`，exact 表优先、prefix 表取最长），带尾斜杠的 `/skills/` 会让 `/skills/<id>` 在引擎层就 404（空响应体、不进 handler），这正是线上 `/skills/code-review` 404 而 `/skills/` 只回 400 的根因；非法包 id（含同前缀下的 `versions/...` 下载路径）在本地即 400，绝不带任意路径打上游；上游 401/会话过期投影 401、其余失败投影 503 并经 `onError` 留下操作名、判定点与原始 error，非 GET 一律 405 且不触发取数；技能包下载与落盘不在此面内——由 `skill-install.ts` 经 platform-client 的四条 `/skills/{install,uninstall,installed,content}` exact 子路径承担；详情 handler 的雪花 id 正则同时是第一道防线（`/skills/install` 若掉进这条 prefix 只会 400）。**另加两条本机技能文件子路径（`<packageId>/files` 与 `<packageId>/file?path=<相对路径>`）**：注册面**仍恰好两条路由**——引擎 exact 表只认整条字面路径（动态包 id 无法注册成 exact），prefix 表同一 path 只能注册一次，而 `/skills` 这条 prefix 已由本文件持有，故两条子路径由**同一条 prefix handler 按剩余段分派**（后缀 `/files` → `local.files(id)`；后缀 `/file` 且查询键集**恰好**一个 `path` → `local.file(id, path)`；其余一律 400）；`local` 端口缺席时两条子路径一律 400（fail-closed：没绑定就不暴露、不猜、不打上游）；失败状态码走 platform-client 导出的 `enterpriseLocalErrorStatus`（与本文件 `/skills/content` 同一张表），响应体只回受控形状的稳定码；**相对路径的形状与落点安全不在本文件**（只在 `skill-install.ts` 的 `requireRelativeSkillPath` / `resolveInstalledSkillTarget`），路由层不做第二套路径判定。 **本刀（ui 侧接上消费）**：这两条本机技能文件子路径（`<packageId>/files` 与 `<packageId>/file?path=`）现在有真实界面消费者——技能详情子页面的**左文件树 + 右文件预览**（`packages/ui` 的 `marketplace-entry.tsx` 经 `store.api.skillFiles` / `store.api.skillFile` 发同源 GET，路径段只放包 id、相对路径只进查询串且 `encodeURIComponent` 收窄）；**路由形状与路径安全一字未改**（仍由 `/skills` prefix handler 按剩余段分派、仍走 `skill-install.ts` 那一份 `requireRelativeSkillPath` / `resolveInstalledSkillTarget`，注册面仍恰好两条路由），只读正文路由 `/skills/content` 按用户要求**保留**（Host 侧注册与既有单测不动），界面这一侧统一走文件路由那同一份路径实现。
