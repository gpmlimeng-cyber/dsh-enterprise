screenshots.json: 社区市场从插件源码目录读取的四张原始截图清单，通过 GitHub 固定提交 URL 复用 docs/assets 媒体并控制展示顺序，不改变 npm 运行包。
tsconfig.json: bundle Host 公开声明的 emit-only TypeScript 边界，通过 workspace 声明消费产品模块，并局部跳过链接上游损坏声明检查。
cordis.patch.yml: 官方 profile layer，覆盖企业 default、停用个人 provider/模型设置、**停用官方 `deepseek-account` 行**并插入企业 Host/Client row；账户后台不再由 patch 定死地址，改由企业 bundle 按用户 settings 挂载官方同一实现。
scripts/build.mjs: 内联产品模块但 externalize 官方 Cordis/credentials/账户实现/LLM/settings/Schemastery 与 Client ui-primitives 单例的双端构建器。
src/index.ts: Web/Desktop 共用 Host 组合入口，绑定 credentials/企业模型网关/分发（企业 profiles 并入 profile 已挂载的官方 `llm-pi-ai`，不再自建第二份实例）；向官方 settings 声明 volatile `serverUrl`/`platformOrigin`/`inferenceOrigin` 字段（命名空间即 `owndsh` entry id，官方 Settings 不生成页面）并把 Server 引用交给 platform-client，地址写入走 `settings.update(entryId, patch)`、不可持久化时报 `ENT_SETTINGS_UNAVAILABLE` 且四个判定点（引用缺失 / `configure` 抛错 / 写入端口未装配 / `settings.update` 抛错）都留 warn/error 宿主日志，在 bootstrap sessionPolicy.enabled 时经 tryRegisterHostSessionSync 条件挂载会话同步，并以自定义地址串行热重挂官方账户插件（先释放旧实例再挂载，失败回滚）；同处注册三条同源路由：用量只读镜像、反馈 multipart 透传，以及**帮助中心出口**（`help-route.ts`，地址由 Host 按自己配置的平台地址加固定 `/help/` 派生后用 PKCE 那条系统浏览器通道打开，浏览器无法注入 URL）。
src/account-origin.ts: 账户后台地址语义层 —— 企业默认域名、写入前的 origin 校验纯函数、串行幂等的 `AccountOrigin` 热重挂控制器，以及 `/enterprise/api/v1/local/account-origin` 的 GET/POST 同源路由（settings 不可写时投影 503 `ENT_SETTINGS_UNAVAILABLE`，并经 `report` 端口把操作名与原始 error 交给组合层 logger）；不感知 Cordis fiber。
src/models-status.ts: 企业模型挂载状态诊断 —— `GET /enterprise/api/v1/local/models/status` 只读投影 bootstrap 是否就位、模型数与协议、官方 pi-ai 行是否定位、已写入的 providers（含 enterprise 前缀过滤）；Host 日志不落盘时用它定位企业模型不显示的断点，非 GET 405、异常 503 且留判定点 warn。
src/usage-route.ts: 用量只读镜像 —— `GET /enterprise/api/v1/local/usage` 由 Host 代取中心 `/enterprise/api/v1/usage/me`（Access Token 不进浏览器），把上游 `{data, requestId}` 投影成本地单键 `{data}`；上游 401/会话过期投影 401、其余失败投影 503 并经 `onError` 留下操作名、判定点与原始 error，非 GET 一律 405 且不触发取数。
src/feedback-route.ts: 反馈 multipart 透传 —— `POST /enterprise/api/v1/local/feedback` 由 Host 代取 Access Token 转交中心 `/enterprise/api/v1/feedback`（令牌不进浏览器）；有界读取正文（三张满额附件 + 1 MiB 分帧余量）后重建提交体：`metadata` 保留浏览器字段但 **`diagnostics` 一律用 Host 采集值覆盖**（封闭五键 pluginVersion/hostVersion/os/installationId/lastErrorCode，逐字段按契约正则收窄，越界退化成 null），附件按**魔数**重写 content-type 并以新 boundary 分帧（文件名去危险字符）；本地先按中心同名口径限流（>3 张与非法位图→400 `ENT_FEEDBACK_ATTACHMENT_INVALID`、单张 >2 MiB 或正文超界→413 `ENT_FEEDBACK_ATTACHMENT_TOO_LARGE`）；`Idempotency-Key` 选填 UUID v4 原样透传、非法值本地 400；上游 401/`ENT_AUTH_REQUIRED`/`ENT_AUTH_SESSION_EXPIRED` 投影 401，中心三个稳定业务码按契约状态透传（400/400/413）且不留痕，其余失败投影 503 并经 `onError` 留下 operation/step/status 与原始 error，非 POST 一律 405 且不触发取数。
src/help-route.ts: 帮助中心出口 —— `POST /enterprise/api/v1/local/help/open` 无正文：地址由 `enterpriseHelpTarget(origin())` 从 Host 当前平台地址派生并拼固定 `/help/`（严格 allowlist = 没有可注入的输入，畸形/未配置/非 http(s) 一律 undefined），再用 `openSystemBrowser`（与 PKCE 登录同一条系统浏览器通道）打开；成功回 `{data:{opened:true}}`，平台地址不可用或交接失败投影 503 `ENT_PLATFORM_UNAVAILABLE` 并经 `onError` 留判定点与原始 error，非 POST 一律 405 且不交接；客户端在交接途中断开（响应未写完即 close）才中止，避免误杀自己的 execFile。
src/skill-route.ts: 企业技能目录只读镜像 —— `GET /enterprise/api/v1/local/skills`（列表，exact）与 `/skills/{packageId}`（详情，prefix）由 Host 代取中心 runtime 面 `/enterprise/api/v1/skills[/{id}]`（Access Token 不进浏览器），把上游 `{data, requestId}` 投影成本地单键 `{data}`；**详情 prefix 注册成与列表逐字相同、不带尾斜杠的路径**——引擎 `dsh-host-webserver` 的 `match()` 只做「路径段前缀」（`pathname === prefix || pathname.startsWith(prefix + '/')`，exact 表优先、prefix 表取最长），带尾斜杠的 `/skills/` 会让 `/skills/<id>` 在引擎层就 404（空响应体、不进 handler），这正是线上 `/skills/code-review` 404 而 `/skills/` 只回 400 的根因；非法包 id（含同前缀下的 `versions/...` 下载路径）在本地即 400，绝不带任意路径打上游；上游 401/会话过期投影 401、其余失败投影 503 并经 `onError` 留下操作名、判定点与原始 error，非 GET 一律 405 且不触发取数；技能包下载不在此面内——一期员工端只复制装配指令，落盘交给用户自己的 Agent 会话。
tests/bundle.spec.ts: 验签开关默认值与显式开启、credentials/模型/分发组合、Session 同步双向门禁（无 dsh-session peer）、兼容 peers（llm-pi-ai 走 peer 声明而非直连 import）、Client graph（外观组 ui-theme + 快捷键面板 ui-shortcuts 双注入、settings.section/launcher + plugins.item/detail.badge 四座位注册）与构建产物验收。
tests/account-origin.spec.ts: 目标1 账户地址输入门禁 —— `deepseek-account` 行必须停用且不覆盖 config、`ui-settings-account` 整行 disabled 且不带 config 覆盖（官方无「只隐藏登录动作」的开关，故整行停用）、`account-controller`/`deepseek-account-platform` row 不被触碰、企业默认域名必须进源码、发布物内不得出现非回环的内网字面端点、`desktopPlatform` 必须在企业挂载点重述，并直测地址校验纯函数与本地路由的 200/400/405 契约。
tests/help-route.spec.ts: 帮助中心路由门禁 —— 地址只由 Host 平台地址派生（源码无硬编码域名、畸形/未配置/非 http(s) 一律不可用）、POST 200 且交接当场信号未被中止、客户端自带 URL 被忽略（请求根本没有这个字段）、未配置与系统浏览器拒绝各自 503 + 判定点日志、非 POST 一律 405 且不交接。
tests/usage-route.spec.ts: 「我的用量」本地路由门禁 —— 真实 HTTP 下的 200 透传（剥掉 requestId、不自行拼 Authorization）/401/405/上游异常与畸形信封 503 四类投影、判定点日志，以及上游未抛异常的非 2xx 兜底。
