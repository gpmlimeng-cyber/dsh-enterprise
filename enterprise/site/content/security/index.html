SECURITY & COMPLIANCE

边界写清楚，才谈得上信任。

下面每一条都对应实现或契约中的具体约束，你可以对照代码与在线文档核对；我们不使用"银行级安全"这类无法验证的说法。

BOUNDARIES

平台做什么，不做什么

平台负责平台不介入
身份、成员、角色与设备治理不接管员工工作区，不读取工作区文件
模型供给与供应商凭据保管不把供应商 API Key 下发到员工设备
模型请求的网关转发与额度校验不远程执行员工工具，不 fork 官方 Harness Web UI
审计事件、用量账本与会话治理不在用量账本中记录提示词与消息正文

SECRETS

凭据怎么保管

只写不回显

供应商凭据为只写输入，读取接口只返回"凭据已配置"，不会回显任何密钥内容。

主密钥的边界

部署主密钥（ENT_MASTER_KEY）用于保护供应商密钥与部分会话内容；它一旦丢失，这些数据不可恢复。

会话格式

客户端同步的会话使用官方格式并带哈希校验；服务端校验批次哈希与滚动哈希证明，异常会被拒绝。

插件构件

构件做大小、SHA-256、兼容性与下载权限校验；签名校验可按需开启（默认关闭）。

REQUEST DEFENSE

浏览器与会话侧的防线

防线具体做法
会话凭据管理端使用同源 HttpOnly Cookie，SameSite=Strict、Path=/；HTTPS 下自动使用 __Host- 前缀强化
写操作保护非安全方法校验 Origin（缺失时看 Referer）必须与请求同源，不一致返回 401
跨域策略CORS 默认拒绝所有跨域来源，管理端与员工端均按同源/服务端调用设计
登录事务口令登录需要在同一事务内提交 CSRF 令牌；授权码一次性使用
响应头控制台与文档站点设置 X-Content-Type-Options: nosniff、Referrer-Policy；帮助中心额外启用 CSP 与 X-Frame-Options: DENY

AUDIT

审计与保留

31 类审计事件

覆盖登录、成员与身份变更、设备、模型与授权、配额、插件、会话与配置变更；事件由数据库约束保证取值合法。

可回溯到 requestId

每个响应都带 requestId，可与审计事件、用量账本关联，用于定位一次具体调用。

会话正文单独授权

会话元数据与正文读取权限分离；正文仅通过单独授权的操作投影解密内容，并有独立权限码。

用量账本不含正文

账本只记录计数与归属，不保存提示词、消息内容、供应商路由或凭据。
