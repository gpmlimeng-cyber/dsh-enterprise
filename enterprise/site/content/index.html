OPEN SOURCE · SELF-HOSTED CONTROL PLANE

把 Agent 的自由留给员工，把边界交给平台。

OwnDsh 是 DeepSeek Harness 的开源自托管团队控制面：集中管理身份、模型与 API Key、访问授权、配额、 插件、设备与审计，员工继续使用自己熟悉的 Harness 工作区。

开始部署 看企业版
MIT 开源 Docker Compose 自托管 97 个 API 操作 42 个稳定错误码 31 类审计事件
git clone https://github.com/boe1900/owndsh.git && cd owndsh && docker compose up -d --wait

需要 Docker Engine 与 Docker Compose 2.20.3+；实测 2 核 / 3.6 GB 即可跑起四个容器。

CONTROL PLANE

控制台只用五个入口，就覆盖了企业要管的事

模型、访问策略、插件、成员、活动记录——没有可以自由编排的菜单树，也没有藏起来的开关。

Identity

身份与成员

LOCAL、LDAP、OIDC 三类身份源；成员状态、固定角色、外部身份链接与设备治理。

Models

模型与凭据

集中保管供应商凭据（只写不回显），以平台别名对员工暴露模型，上游真实模型名不外泄。

Policy

授权与配额

按全员、用户组或指定成员授权；五小时 / 日 / 周 / 月 Token 窗口，加 RPM 与并发上限。

Audit

审计与用量

31 类审计事件与用量账本（不含提示词正文）；会话正文单独授权、可回溯到 requestId。

CAPABILITIES

按角色分工，各管一段

每类管理员只拿到自己需要的权限码（共 17 个 ent:* 权限），审计员被刻意收窄为只读合规视角。

使用者能力
平台管理员自托管控制台、LOCAL/LDAP/OIDC 身份、成员与设备治理
模型管理员集中保管供应商 API Key，管理模型、模型集、授权、Token 配额、RPM 与并发
插件管理员上传、签名（可选）、发布企业插件，设置可见范围并查看客户端状态
审计员查询管理操作、模型调用、用量与 requestId 关联记录
员工用企业账号登录 Harness，使用获准模型并自主安装企业插件，无需持有上游 API Key

BOUNDARIES

我们自己划了界，也帮你划界

不做什么

不 fork 官方 Harness Web UI，不接管员工工作区，也不远程执行员工工具；只通过公开插件扩展点集成。

密钥不出平台

供应商 API Key 只存在服务端、只写不回显；员工设备永远拿不到它。

每次请求都重新校验

模型请求经平台网关转发，逐次校验身份、授权与额度，而不是发一张长期通行证。

记录可回溯

审计事件与用量账本可按人、按模型、按时间查询，并沿 requestId 串起一次完整调用。

接入方式 员工可以下载 OwnDsh Desktop（预装插件与运行环境），也可以给已有的官方 Harness / 社区 Desktop 安装企业插件。
