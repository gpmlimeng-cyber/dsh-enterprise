DEPLOY

从一条命令开始。

准备 Docker Engine 与 Docker Compose 2.20.3+，克隆仓库并启动。数据库迁移由服务端在启动时自动完成。

git clone https://github.com/boe1900/owndsh.git cd owndsh docker compose up -d --wait
镜像平台：Linux amd64 实测：2 核 / 3.6 GB / 50 GB 启动后自检：GET /healthz

REQUIREMENTS

环境要求与访问入口

项要求 / 说明
容器运行时Docker Engine 20.10+ 与 Docker Compose 2.20.3+
资源实测 2 vCPU / 3.6 GB 内存可稳定运行四个容器（PostgreSQL、Redis、Server、Console）
端口只需放行一个 HTTP 端口（默认 80）；TLS 建议由前置反向代理终止
控制台/：模型、访问策略、插件、成员、活动记录
健康检查GET /healthz 返回 {"status":"UP"}
初始管理员由环境变量 ENT_BOOTSTRAP_ADMIN_USERNAME 指定；首次登录会强制改密
注意 不要执行 docker compose down -v：那会连同 PostgreSQL、Redis 与构建产物的数据卷一起删除。

CONFIGURE

配置企业的六步路线

顺序有意义：没有身份源就没有成员，没有模型就没有可授权的对象。

01

配置身份来源

成员 → 身份接入 → 新建身份源。先测试连通性再启用。

02

添加模型供应商

模型 → 供应商 → 新建。凭据只写不回显，建议先做连接测试。

03

定义受管模型与模型集

平台别名映射上游模型名，员工端只见别名。

04

下发访问授权

访问策略 → 授权，范围可选全员、用户组或指定成员，支持批量。

05

按需配置配额

访问策略 → 配额，限制 Token 窗口、RPM 与并发。

06

发布企业插件

插件 → 上传 → 发布 → 分配（可选）。

提示 授权与配额是两件事：配额策略不会代替访问授权。员工"登录后看不到模型"，九成是授权没下发。

CLIENTS

员工怎么接进来

DSH Enterprise Desktop（推荐）

预装插件与运行环境的桌面客户端，填写 Server 地址即可登录，无需自行准备 Node 与 pnpm。

前往下载页

给已有 Harness 装插件

corepack enable corepack install --global pnpm@11.7.0 dsh plugin --profile web add --ignore-scripts dshent-plugin@next

安装后重启对应 profile；Server 地址必须是完整 HTTP(S) origin，不能带 API 路径。

OPERATIONS

运维、升级与离线交付

升级

docker compose pull && docker compose up -d --wait

数据库迁移随服务端启动自动执行；升级前建议先做备份。

备份范围

数据卷（PostgreSQL / Redis / 构建产物）与部署配置文件；ENT_MASTER_KEY 丢失将导致供应商密钥与部分会话内容不可恢复，必须纳入备份。

离线交付

镜像可导出为离线包在无外网环境导入；若拉取镜像缓慢，可改用可信镜像源（镜像摘要与官方一致）。

日常检查

四个容器健康状态、/healthz 探针、服务端日志与数据库连接数；异常优先看容器日志与 requestId。

更多 完整的部署参数、备份恢复与排障步骤见帮助中心（运维手册）；接口与错误码见 API 参考。
