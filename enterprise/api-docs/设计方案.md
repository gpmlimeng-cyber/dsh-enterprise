### 1.3 权限模型

服务端 16 个 `ent:*` 权限码（`@SaCheckPermission`）：
`ent:model:read/write`、`ent:grant:read/write`、`ent:member:read/write`、`ent:identity:read/write`、`ent:plugin:read/write`、`ent:usage:read`、`ent:device:read`、`ent:device:revoke`、`ent:session:read`、`ent:session:delete`、`ent:audit:read`。
控制台 `bootstrap` 会把 `ent:` 前缀权限码返回给前端（`ConsoleBootstrapController.java:64`）。
⚠️ 契约里**没有**权限字段，Java 方法名（`list`/`get`/`revoke`）也**不等于** operationId（`listDevices`/`getDevice`/`revokeDevice`），所以权限矩阵需要按 `类级 @RequestMapping + 方法级 @GetMapping + HTTP 动词` 拼路径后与契约 path 关联。

## 2. 目标与非目标

### 目标（"标准 SaaS"的 8 个模块）

1. **概览与快速开始**：3 条接入路径（控制台浏览器会话 / 桌面端 PKCE / 模型网关 SSE）的 5 分钟上手。
2. **鉴权与安全**：Cookie 会话 vs Bearer Token、同源写保护、CORS 默认拒绝、Cookie 命名在 HTTP/HTTPS 下的差异。
3. **端点参考**：按业务域分组的 97 个操作，支持搜索、深链锚点、多语言代码示例（cURL / JS fetch / Python / Go / Java / PowerShell）。
4. **Try it out**：同源页面直接携带会话 Cookie 调用，成功/失败全链路可视。
5. **错误码字典**：42 个稳定错误码 × HTTP 状态 × 中文含义 × 处置建议（自动从 `x-enterprise-error-statuses` 生成骨架）。
6. **配额与限流语义**：8 个 429 配额码 + 幂等/重试/退避建议。
7. **权限矩阵**：操作 → 所需 `ent:*` 权限 → 可见角色（自动从 Java 注解提取，人工只补例外）。
8. **版本与变更日志**：文档页脚展示契约协议指纹（`protocol-sha256`）+ 版本 + 部署时间，做到"线上文档与线上代码同版可验证"。

### 非目标（本期不做）

- ❌ 不新增/修改任何业务接口（零后端契约变更）。
- ❌ 不做公开的对外开发者门户（文档默认要求已登录控制台会话）。
- ❌ 不做 SDK 发布流水线、沙箱环境、Mock Server（列入 P3+ 可选演进）。
- ❌ 不引入 Node/npm 到宿主机运行态（构建在容器内完成）。
- ❌ 不触碰数据卷、不改 server 镜像、不动 `.env` 中的密钥类变量。

## 3. 方案选型

### 3.1 形态选型

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 同源独立门户**（推荐） | nginx 新增 `location /api-docs/`，静态托管文档 SPA + 增强后的 spec | 零后端改动、零 console 重建、可独立升级、可用 nginx 原生鉴权、不污染 console 包体 | 需要在 nginx/compose override 上加一处配置 | ✅ **采用** |
| B. SPA 内嵌路由 | 在 `console/src/routes/` 加 `_console.api-docs.tsx`，用 `@scalar/api-reference-react` 渲染 | 与导航/Tab 体系天然一体、样式统一 | 必须重建 console 镜像；1.85 MB spec 进构建产物；文档更新要走镜像发布；Scalar React 包与 React 19/TanStack 组合未经验证 | ⛔ 不作为主方案（P2 仅加一个外链入口） |
| C. 服务端文档服务 | 新增 `/enterprise/admin/v1/docs` 返回 spec，springdoc 打开 | 鉴权最严谨、可按角色裁剪 | 必须重建 **server** 镜像（Maven 构建未验证）+ nginx 加路由，风险与成本最高 | ⛔ 列为 P3 可选 |

### 3.2 渲染器选型

| 渲染器 | 许可 | Try it out | 观感/能力 | 体积 | 结论 |
|---|---|---|---|---|---|
| **Scalar** `@scalar/api-reference` 1.68.0 | MIT | ✅ 原生 | 现代 Stripe 风、内置搜索、多语言示例、深色模式、`x-tagGroups` 支持 | standalone 3.74 MB / gzip 1.05 MB（强缓存） | ✅ **采用** |
| Redoc `redoc` | MIT | ❌（需商业版） | 三栏经典、只读文档最佳 | ~1 MB | 备选（若明确不要 Try it out） |
| RapiDoc | MIT | ✅ | 轻量、可定制、观感略旧 | ~700 KB | 备选 |
| Swagger UI | Apache-2.0 | ✅ | "标准"但观感旧、移动端差 | ~1.5 MB+ | 兜底 |

选型理由：We already have a machine-grade OpenAPI 3.1 spec（含 `additionalProperties:false` 严格 schema、SSE 说明、错误码扩展），Scalar 能直接吃到这些信息，且 `x-tagGroups`/`x-scalar-*` 扩展足够做品牌化；许可证 MIT 与现有依赖策略一致。
**硬约束**：资产必须**自托管**（离线/内网可用），不使用 CDN，构建期下载并校验 sha256。

## 6. 关键技术设计

### 6.1 契约增强流水线（`build-docs.mjs`）

输入 → 输出：`contracts/enterprise-openapi.yaml` + `config/*` → `dist/enterprise-openapi.json`（+ 指纹）。

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1. 解析 | 用 `@apidevtools/swagger-parser`（已在 `plugin/` 依赖树中，版本 12.1.0）bundle 模块化 YAML + 校验 | 契约是分片引用，浏览器不方便直接吃 |
| 2. 注入 servers | `servers: [{ url: '/', description: '当前站点（同源）' }]` | **不硬编码 IP/协议**：HTTP→HTTPS 迁移后文档无需重生成，Try it out 自动跟随页面 origin |
| 3. 注入 tags | 来自 `config/tags.yaml`：tag 描述 + `x-tagGroups` + 每个 operation 的 `tags` | 契约本身无 tag，97 个操作否则是一坨平铺列表 |
| 4. 合并文案 | 来自 `config/overlay.zh.yaml`：按 `operationId` 覆盖 `summary`/`description`，补参数与响应说明、`x-codeSamples` | 契约只有 29 条英文 summary |
| 5. 权限矩阵 | 解析 `server/**/Admin*Controller.java`：类级 `@RequestMapping` + 方法级 `@GetMapping/@PostMapping` + 动词 → 路径；再与 `@SaCheckPermission("ent:*")` 关联 → 写回 `x-enterprise-permission` | 契约无权限信息；自动提取避免人工漂移，人工只补例外 |
| 6. 错误码表 | 展开 `x-enterprise-error-statuses` + overlay 中文释义 → `info.description` 的 Markdown 表格 + 每个操作的错误响应示例 | 42 个码是现成的，白送一份字典 |
| 7. 瘦身 | 删除 `x-enterprise-fixtures`；压缩 4.8 MB → minify；保留 `additionalProperties:false` 语义 | 页面首屏体积 |
| 8. 指纹与页脚 | 读 `generated/protocol-sha256.txt` + git commit + 生成时间 → 写入 `info['x-owndsh-build']` | "线上文档 = 线上代码"可核验 |
| 9. 漂移门禁 | `--check` 模式：不写文件，只比对（接 CI 或部署前自检） | 与既有 `pnpm --filter @dshent/contracts check:generated` 同思路 |

预期产物（**已实跑验证**，见 §6.6）：spec 1.67 MB，gzip 后 **61 KB**；97 操作 / 21 tag / 4 tagGroup / 42 错误码全覆盖。

### 6.2 访问控制（不加后端接口）

```nginx
    # ---- API 文档门户（P1）----
    location /api-docs/ {
      auth_request /_docs_auth;                 # 会话校验在子请求里
      error_page 401 = @docs_login;             # 仅本 location 生效（关键：不要放 server 级）
      root /usr/share/nginx/html;
      index index.html;
      try_files $uri $uri/ /api-docs/index.html;
      add_header Cache-Control "no-cache" always;
      add_header X-Robots-Tag "noindex, nofollow" always;
      gzip on;                                  # 只在本 location 开，避免影响 API/SSE
      gzip_types application/json text/css application/javascript text/plain;
      gzip_min_length 1024;
    }

    location = /_docs_auth {                    # 复用控制台引导接口做"是否已登录"判定
      internal;
      proxy_pass http://$upstream_server/enterprise/admin/v1/bootstrap;
      proxy_pass_request_body off;
      proxy_set_header Content-Length "";
      proxy_set_header X-Original-URI $request_uri;
    }

    location @docs_login {
      return 302 /login?redirect=%2Fapi-docs%2F;
    }
```

设计要点与理由：

1. **为什么用 `bootstrap` 做判据**：它对**任意控制台角色**都返回 200（`model_admin`/`plugin_admin`/`auditor` 都能进控制台），未登录返回 401（`console/src/auth/session.ts:22-27` 印证），因此一次子请求即可判定"已登录控制台"。
2. **Cookie 会自动转发**：nginx 默认透传未显式覆盖的请求头（`nginx.conf` 里的 `proxy_set_header` 只覆盖 Host/Forwarded/XFF 等，未覆盖 `Cookie`）。
3. **`error_page 401` 必须写在 location 内**：若写在 server 级，会把 `/enterprise/*` 的 401 也改写成 302，破坏前端 `AuthRequiredError` → `/login` 的既有语义。
4. **`internal` + `auth_request` 只作用于文档路径**：业务 API 与 SSE 网关的代理行为完全不变（`proxy_buffering off` 的网关 location 不受影响）。
5. **不缓存 spec**：`Cache-Control: no-cache`（用户级会话下的内容不做公共缓存），Scalar 自身会按 URL 请求一次。
6. **可选更严**：若要仅 `enterprise_admin` 可见，把子请求换成 `/enterprise/admin/v1/members`（需 `ent:member:read`）；代价是其他角色看不到文档。

### 6.3 Try it out 的可行性（关键结论）

同源文档页发起 `POST/PUT/DELETE` 时，浏览器会带 `Origin: http://62.234.16.179`，服务端 `requireSameOriginForUnsafe` 会比较 scheme/host/port：

- 请求侧：`server.forward-headers-strategy: native` → Tomcat RemoteIpValve 依据 `X-Forwarded-Proto: http`、`X-Forwarded-Host: 62.234.16.179` 推导 scheme=http；`X-Forwarded-Port` 因 nginx 传的是空变量而**被 nginx 省略**（nginx 不转发空值头），RemoteIpValve 回落到协议默认端口 **80**。
- Origin 侧：`http://62.234.16.179` 无显式端口 → 有效端口 **80**。
- ⇒ scheme/host/port 三者一致，写操作**应当放行**；且 Cookie 为同源同站（`SameSite=Strict`）自动携带，**无需任何 token 手工配置**。

⚠️ 这一条是**设计推论 + 代码证据**，必须在 P0 用一次真实的写操作（或安全的最小副作用操作）实测确认；若实测 401，则问题同样存在于控制台自身的所有写操作，处置见 §10 P0-3。这正是把 P0 独立出来的原因。

### 6.4 主题与品牌一致性

- 复用 console 的主题真源：`index.html` 里读取 `localStorage['bui-theme']`（console 用同一个 key，默认 dark），文档页优先读取，实现深浅色联动。
- `theme.css` 用 OwnDsh 的配色 token（`--color-canvas/page/ink/line/hover` 系列）覆盖 Scalar 的 CSS 变量，使文档与控制台视觉同族，而不是"外链了别人的文档"。
- 字体沿用 console 已自托管的 `@fontsource-variable/inter`、`jetbrains-mono`；代码块用 JetBrains Mono。

### P0 发现的真实缺陷（已修）

**nginx 绝对跳转带容器端口**：容器内监听 8080、宿主机只发布 80，nginx 默认生成
`Location: http://<host>:8080/login?...` —— 浏览器会打到未发布的端口。
修复：server 块加 `absolute_redirect off;`，跳转变为 `/login?redirect=%2Fapi-docs%2F`。
该缺陷同样会影响其它由 nginx 自发的跳转，属本次顺带修复的基础设施问题。

### 与设计稿的差异（如实记录）

1. **契约权限的三处修正**（自动提取优于人工标注）：
   - 会话正文读取是**三段式** `ent:session:content:read`（原稿按文档注释写成 `ent:session:content`，错）；
   - **配额管理复用 `ent:grant:read|write`**（上游 `AdminQuotaController` 如此注解，不是 `ent:quota:*`）；
   - `getConsoleBootstrap` / `changeCurrentAccountPassword` 无需 `ent:*` 权限（登录会话即可），已归为 `session`。
2. **字体**：额外从 console 镜像取出 Inter / JetBrains Mono 并自托管；Scalar bundle 内部引用
   `fonts.scalar.com`，因此 `--scalar-font` 覆盖是**离线可用性的必要条件**，不只是美观。
3. **`proxyUrl` 显式置空**：禁止把内网请求交给 Scalar 托管代理。
4. **`x-tagGroups` / `x-scalar-order` / `x-scalar-stability`** 均已确认被 1.68.0 支持，分组与顺序由配置驱动。
5. **写操作提示**：`hideTestItOut` 在 1.68.0 中不存在，故改用每个操作 `description` 顶部的 Markdown 警示块
   （用户已确认允许写操作，故只警示不拦截）。
