# 快速开始：30 分钟让企业可用

前提：服务已经按《部署与初始化》跑起来，四容器 healthy，`http://<你的地址>/healthz` 返回 `{"status":"UP"}`。
下面六步就是官方推荐的上线顺序——**顺序有意义**：没有身份源就没有成员，没有模型就没有可授权的对象。

## 六步路线

### 1. 配置身份来源

**操作路径**：成员 → 身份接入 → 新建身份源

本地账号（LOCAL）适合小团队起步；LDAP / OIDC 适合接入既有企业目录。
配完先点**测试**确认连通性，再启用。详见《接入企业身份源》。

### 2. 添加模型供应商与 API Key

**操作路径**：模型 → 供应商 → 新建

上游供应商的凭据是**只写输入**：保存后界面只显示"凭据已配置"，不会回显。
建议先点一次连接测试，确认凭据与网络都通。详见《配置模型供应商与凭据保管》。

> 🔒 员工设备永远拿不到供应商 API Key。每次模型请求都由网关重新校验身份、授权与额度。

### 3. 定义受管模型与模型集

**操作路径**：模型 → 模型 / 模型集

受管模型是**平台别名 → 上游模型名**的映射，员工端只见别名，看不到上游真实模型名。
把一组模型打成模型集，后续授权按模型集下发，避免逐个成员配置。

### 4. 下发访问授权

**操作路径**：访问策略 → 授权

授权范围可以是**全部成员 / 用户组 / 指定成员**，支持批量下发。

> ⚠️ **授权与配额是两件事**：配额策略不会代替访问授权。员工"登录后看不到模型"，
> 九成是这里没授权，而不是配额问题。

### 5. 按需配置配额

**操作路径**：访问策略 → 配额

可以限制 Token 窗口（五小时 / 日 / 周 / 月）、RPM 与并发。触发时网关返回 `429` 与对应的
`ENT_QUOTA_*` 错误码。详见《配额：Token 窗口、RPM 与并发》。

### 6. 上传并发布企业插件（可选）

**操作路径**：插件 → 上传 → 发布 → 分配

插件版本的生命周期是：上传 → 发布 → （必要时）退休；分配决定它对谁可见。
详见《插件治理：上传 / 发布 / 退休 / 分配》。

## 最后一步：让员工接进来

把这两样东西发给员工：

1. **Server 地址**（必须是完整 HTTP(S) origin，不能带 API 路径）
2. 让他们按《员工接入总览》选一条路：装 DSH Enterprise Desktop，或给已有 Harness 装企业插件

员工首次登录若被要求改密，是因为初始口令是一次性的——改完即可正常使用。

## 验收清单

| 检查项 | 期望 |
|---|---|
| 平台健康 | `GET /healthz` → `{"status":"UP"}` |
| 身份源 | 测试通过且已启用 |
| 供应商 | 连接测试通过，凭据显示"已配置" |
| 模型 | 至少一个受管模型处于启用状态 |
| 授权 | 目标成员/用户组能查到对应模型集授权 |
| 员工侧 | 员工保存 Server 地址后能登录并看到模型 |
