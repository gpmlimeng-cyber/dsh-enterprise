# OwnDsh 帮助手册（帮助中心）—— 规划设计

> 目标：为管理员、员工与运维人员提供一套**与 API 文档同风格**的帮助手册，指导使用与配置系统。
> 承接：API 文档门户已上线（`http://62.234.16.179/api-docs/`，P1，见 `owndsh-api-docs/设计方案.md`）。

| 项 | 结论 |

### 1.3 上游已有的"零依赖静态站"先例（可直接借用的工程约定）

`website/`（品牌官网）已经证明这套做法在本仓库成立，且与本方案同构：

- `build.mjs`：**Node 标准库白名单发布器**（只把公开文件写进 `dist/`，过滤 `CLAUDE.md`、源码地图等内部文件），零第三方依赖，`engines: node >= 22`。
- `_headers`：Cloudflare 静态响应头策略（CSP `default-src 'self'`、`X-Frame-Options: DENY`、`nosniff`、`Permissions-Policy`）。
- `site.test.mjs`：用 Node 原生 `node --test` **验证发布白名单**，防止内部文件被上传。
- 设计哲学：内容和命令在**无 JavaScript 时仍可阅读**，JS 只做渐进增强。
- 每个文件都有 `[INPUT]/[OUTPUT]/[POS]/[PROTOCOL]` 头部注释 —— 手册构建脚本也应遵守。

## 2. 目标与非目标

### 目标

1. **任务导向**（不是功能罗列）：每一篇都以"我要完成 X"开头，给出精确的界面路径与可复制命令。
2. **三本手册分流**：管理员（配置与治理）、员工（接入与日常使用）、运维（部署/备份/升级/排障），首页按角色给入口。
3. **与 API 文档同风格**：同一套色板、字体、圆角、描边、深色默认，页脚同样展示"内容版本 + 校验时间"。
4. **可验证、不腐烂**：自动生成页 + 漂移门禁，把手册纳入与契约同级的事实校验。
5. **可离线**：零 CDN；断外网仍完整可用；无 JavaScript 时正文可读。
6. **可回滚**：与 API 文档同款一键回滚（nginx + override 还原）。

### 非目标

- ❌ 不重复 API 参考：字段/请求/响应细节一律**链到 `/api-docs/`**，手册只讲"什么时候用、注意什么"。
- ❌ 不写营销文案（官网 `website/` 的职责，不重复）。
- ❌ 不做社区/评论/多语言（i18n 列入 P3+，先在结构上预留）。
- ❌ 不做账号自助注册、工单系统等产品功能。
- ❌ 不引入重量级文档框架（见 §3 选型理由）。

## 3. 技术选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Markdown 真源 + 零依赖 Node 生成器** | 与 API 文档同管线；**样式完全可控**（"风格一致"成本最低）；零 npm 依赖、离线可构建；可复用门禁/热更新/回滚；无 JS 可读 | 搜索、i18n、版本化需自己实现（搜索用自托管 MiniSearch 解决） | ✅ **推荐** |
| B. VitePress | 开箱搜索/i18n/主题，社区成熟 | 引入 npm 依赖树与 Vue 运行时；默认主题与本控制台风格差距大，改造成本高；构建需联网装依赖 | ⛔ 不作首选；作为**将来**可选迁移目标（内容格式兼容 Markdown） |
| C. Docusaurus / Starlight | 功能最全（版本化、插件生态） | 依赖最重（React/Astro 全栈），与 zero-dep 部署层风格冲突 | ⛔ 排除 |
| D. 塞进现有 Scalar 门户 | 零新站点 | Scalar 是 API 参考渲染器，不提供多页手册/侧栏/搜索/版本 | ⛔ 排除；改为**互相链接** |

**选型理由**："风格与 API 文档保持一致"这条要求本身就决定了——用现成框架需要大量覆盖样式才能贴近，自研方案反而是最短路径；同时零依赖构建在**这台服务器**上已经被验证可行（无 node、无 npm 的宿主，构建跑在 `node:24-alpine` 容器里）。
**可逆性**：内容以 Markdown + frontmatter 为真源（§6.1），渲染器只是消费者；将来若需要 i18n/版本化，可整体换 VitePress 而复用全部内容。

### 写作规范（进入门禁）

1. **操作路径统一写法**：`成员 → 身份接入 → 新建身份源`（用 `→` 分隔；每一级都是控制台里的真实文案）。
2. **命令块可复制**：带语言标注；`sh` 块右上角有复制按钮（JS 增强，无 JS 时仍可选中）。
3. **三种提示框**：`> 💡 提示`、`> ⚠️ 注意`、`> 🔒 安全`，语义固定，不混用。
4. **字段说明只写"填什么/为什么"**，具体类型与约束链到 API 参考。
5. **每篇必须有**：`audience`、`verifiedAt`、`sourceRefs`（见 §6.5），缺失则构建失败。
6. **不要截图当唯一说明**：截图只做辅助，关键步骤必须能靠文字完成（截图会过期）。

## 6. 关键技术设计

### 6.1 内容真源与 frontmatter 契约

```markdown
---
title: 为已有 Harness 安装企业插件
audience: user            # admin | user | ops | all
order: 3                  # 同目录内排序
summary: 一句话摘要，用于首页卡片与搜索结果
verifiedAt: 2026-09-16    # 最后人工校验日期（页头展示）
sourceRefs:               # 构建期校验这些引用仍存在（防漂移）
  - README.md#安装员工插件
  - plugin/packages/plugin-distribution/README.md
uiLabels: [插件, 设置, 安装]   # 构建期与控制台构建产物交叉校验（§6.5）
generated: false          # 自动生成页为 true，禁止手改
---
```

### 6.2 构建管线（`build-help.mjs`，零 npm 依赖）

```
content/**/*.md ─┐
config/site.yaml ┼─► 1 解析 frontmatter/Markdown 子集
                 │   2 生成导航树（按 audience + order）
                 │   3 生成搜索索引（标题/摘要/正文切片）
                 │   4 渲染页面（主题壳 + 目录 + 上/下一篇 + 互链）
                 │   5 生成自动页（角色权限 / 配置项 / 错误码 / 界面地图）
                 │   6 校验门禁（引用/UI 文案/内链锚点/frontmatter）
                 └─► dist/（index.html、各页 HTML、assets/、search-index.json）
```

- Markdown 子集：标题、段落、列表、表格、代码块、行内代码、链接、图片、引用块、粗斜体、分隔线。**不支持** HTML 混写（保持可迁移到任何渲染器）。
- 渲染器必须**转义 HTML**（内容是可写的 Markdown，不引入 XSS 面）。
- 产物权限：容器内 `uid 101` 只读消费 → 全部 `644/755`（与 API 文档同款处理）。
- 构建在 `node:24-alpine` 容器内执行（宿主无 node）：
  ```sh
  docker run --rm -v /opt/owndsh/help:/work -v /opt/owndsh/src:/opt/owndsh/src:ro \
    -w /work node:24-alpine node build-help.mjs
  ```

### 6.3 中文搜索方案

| 方案 | 体积 | 中文效果 | 结论 |
|---|---|---|---|
| 自研 bigram 倒排（纯 Node 生成 + 浏览器端匹配） | 索引 ~200–400 KB（gzip 60–100 KB） | 词级召回好，排序弱、无容错 | 备选（保持零依赖） |
| **自托管 MiniSearch**（npm 实测 `7.2.0` / MIT；浏览器单文件体积以 P0-2 实测为准） | 索引同量级 + 库文件 | 支持前缀/模糊/字段权重，中文按 bigram 也可喂 | ✅ **推荐** |
| 服务端搜索接口 | — | 最好 | ⛔ 需要改 server（本方案刻意避免） |

实现：构建期把每页切成 `{id, title, summary, audience, body}`，客户端首次聚焦搜索框时**懒加载**索引（不拖慢首屏）。索引缺失时降级为"按标题过滤左侧树"。

### 6.4 自动生成页（避免人工维护腐烂）

| 页 | 生成方式 | 注意 |
|---|---|---|
| 角色与权限矩阵 | 优先读**运行库**（`sys_role`/`sys_role_menu`/`sys_menu`），离线环境回落到解析 Flyway 迁移（`V4/V19/V20/V23`） | 表头标注数据来源与采样时间；`employee` 与宿主遗留角色要显式说明"不参与企业权限" |
| 配置项参考 | 解析 `.env.example`（键 + 注释 + 默认值/占位），并与现网 `.env` 比对标注"本部署已改" | **绝不输出密钥值**，只输出键名与是否已设置 |
| 错误码速查 | 复用 `owndsh-api-docs/build-docs.mjs` 里的错误码表逻辑（同一份 overlay 中文释义） | 与 API 文档保持单一真源：直接引用 `config/overlay.zh.yaml` 的 `errorCodes` |
| 界面地图 | `config/tags.yaml`（tag ↔ operation）+ 控制台路由表（`product-routes.ts`） | 控制台改路由后门禁会失败 |

### 6.5 漂移门禁（`--check`）

| 校验 | 规则 | 失败后果 |
|---|---|---|
| frontmatter 必填 | `title/audience/order/summary/verifiedAt/sourceRefs` | 构建失败 |
| `sourceRefs` 存在性 | 引用文件/章节必须存在于仓库（如 `README.md#安装员工插件` 的锚点也要校验） | 构建失败 |
| **UI 文案交叉校验** | `uiLabels` 里的每个中文串必须能在 console 构建产物里 grep 到（已实测可行：`邀请成员/身份接入/模型集/发布/退休/新建/访问策略/活动记录/用户中心/插件` 全部命中） | 构建失败 |
| 内链与锚点 | 站内相对链接、`#锚点` 必须存在 | 构建失败 |
| 自动页新鲜度 | 角色权限/配置项/错误码的生成输入哈希变化 → 提示需重新校验（`verifiedAt` 过期告警） | 告警（不阻断） |
| `verifiedAt` 时效 | 超过 N 天（建议 90）未校验 → 页头显示"待复核"黄色标记 | 页面标记 |

### 6.6 与 API 文档 / 控制台的互链

```
控制台 ──► 帮助中心（工作区菜单"帮助"）
   │            │
   │            ├─► /api-docs/#tag/…（具体操作锚点）
   └────────────┴─► /api-docs/（API 参考）
```
- 手册里凡涉及字段/请求细节 → 链到 `/api-docs/` 的**具体锚点**（不是首页）。
- API 文档页脚补一个"看帮助手册"入口；两者共享同一份 `assets/theme.css` 与字体。
- 统一"文档中心"概念：两个站点 + 控制台，页头徽标一致，用户不需要知道它们是不同产物。

### 6.7 鉴权与可见性

- 复用同一套机制：`location /help/ { auth_request /_docs_auth; error_page 401 = @docs_login; … }`，`error_page` 限定在 location 内（否则污染 `/enterprise/*` 的 401）。
- **建议整体需登录**：运维篇含内网地址、卷名、备份路径；且员工手册里也有企业 Server 地址。保持一致比"部分公开"更好维护。
- 可选替代：`/help/admin/`、`/help/user/` 公开（无秘密），仅 `/help/ops/` 需登录 —— 代价是两套 location 规则与两套回滚路径。
- 无需新增任何后端接口。

### 6.8 主题一致性（与 API 文档同一份源）

| 项 | 做法 |
|---|---|
| 令牌 | 复用 console `beautiful-ui.css` 的 `--page/--canvas/--ink/--line/--hover-*` 与 `.dark` 覆盖 |
| 字体 | 复用已从 console 镜像取出的 Inter / JetBrains Mono woff2（4 文件 189 KB） |
| 组件 | 侧栏（可折叠、当前项高亮）、面包屑、代码块 + 复制、三种提示框、上/下一篇、页脚指纹条 |
| 主题切换 | 读同一个 `localStorage['bui-theme']`，与控制台/API 文档联动 |
| **共享方式** | 把 `theme.css` + `fonts/` 提到 `/opt/owndsh/docs-assets/`，两站 `dist/assets/` 指向同一份源（构建期复制），避免两处漂移 |

### 6.9 截图策略

- 默认**无截图**：用"操作路径 + 精确文案"表达，保证永不过期。
- 关键流程（首次配置企业、插件发布、员工接入）允许 3–5 张截图，要求：存 `content/assets/`、文件名带版本（`members-roles@0.1.0.png`）、frontmatter 记录 `screenshotsVerifiedAt`，超过 2 个版本未更新则在页头标记"截图可能过期"。
- 截图来源：由你/管理员在真实控制台截图（我无法在浏览器里操作）；我负责标注位置与说明。

## 附录 B · 为什么"手册"不能只靠 API 文档

API 参考回答"这个接口的字段是什么"；手册回答"我要达成某个目标该怎么点、为什么这么设、出错了先看哪里"。

### 与设计稿的差异（如实记录）

1. **CSP 与内联脚本冲突**：设计里给 `/help/` 定了 `script-src 'self'`，但页面原本用内联脚本做主题前导。
   处置：把主题前导**外置**为 `assets/theme-boot.js`（同步加载在 `<head>`，仍不闪首帧），页面内联脚本数 = 0。
   API 文档门户页仍有内联脚本，故其 CSP 列为**待办**（需先按同范式外置）。
2. **生成块必须作为独立块类型**：Markdown 渲染会把 HTML 注释转义，导致 `<!-- generated:… -->` 失效；
   已改为在渲染器里识别为块级占位符，渲染后再注入，且正文不允许混写 HTML。
3. **搜索先用 bigram 倒排**（设计稿首推自托管 MiniSearch）：当前 5 篇规模下自研倒排已足够且保持零依赖；
   内容增长后平替 MiniSearch 只需改 `assets/help.js` 与构建期索引格式，不影响内容与样式。
4. **`sourceRefs` 需要"部署层根"**：`DEPLOYMENT.md` 不在上游源码树内，已加入 `OWNDSH_DEPLOY_ROOT`（构建命令多挂一个只读根）。
5. **镜像源（代理）路径已验证**：`Dockerfile.console` 新增 `ARG OWNDSH_NPM_REGISTRY`；官方源与腾讯镜像两次构建
   的 `dist` **逐字节一致**（sha256 `06201725578c09ab`），因此镜像源可安全用于将来网络受限时的重建。

### 上线后发现并修复的一个缺陷（2026-09-16）

**症状**：打开 `/help/` 是"没有样式的纯 HTML"。
**根因**：生成器把资源引用写成 `${assetsPrefix}theme.css`，**漏掉了 `assets/` 这一段**，
于是页面请求的是 `/help/theme.css`（不存在），CSS、字体、主题脚本全部 404。
**为什么首轮验收没发现**：我当时用 curl 直接请求的是"我知道的资产路径"（`/help/assets/theme.css` → 200），
而不是"页面自己引用的路径"——**验收对象选错了**。
**修复**：资源引用改为绝对路径 `/help/assets/…`；并新增一条结构性门禁：
遍历每个页面 HTML 里出现的所有 `href`/`src`（含相对路径按页面目录解析），逐个要求在产物中存在，
不通过则构建失败。已用"故意写错一个资源名"反向验证门禁确实会拦下。
**新验收方式**：抓取页面 → 提取自身引用 → 逐个 HTTP 请求断言 200（本次结果：5 个页面各 9 个资源全部 200）。

### 上线后第二个缺陷：bind mount 陈旧导致 403（2026-09-16）

**症状**：`/help/` 返回 `403 Forbidden`（nginx），`/help/admin/quickstart.html` 返回 `500`。
nginx 错误日志给出两条明确线索：

```
[error] rewrite or internal redirection cycle while internally redirecting to "/help/index.html"
[error] directory index of "/usr/share/nginx/html/help/" is forbidden
```

**根因**：生成器在写产物前执行了 `rm -rf dist && mkdir dist`。`dist` 是 console 容器的 **bind mount 源**，
把目录本身删掉会让容器内的挂载点指向**已删除的 inode**——宿主上文件完好，容器内却是空目录。
于是目录索引被禁止（403）、`try_files` 回落目标不存在（500）。
对照：API 文档门户的生成器只 `mkdir` 不删目录，所以它反复重建都没事——这也解释了为什么只有帮助中心出问题。

**修复**：① 生成器改为"保留 `dist` 目录 inode，只清空其内容"；② 执行 `docker restart src-console-1` 重新挂载
（实测 `docker compose up -d` 因判定配置未变**不会**重建，必须 `restart` 或 `--force-recreate`）；
③ 新增 `tools/verify-mounts.sh`：断言两个挂载点在容器内可见且非空，把这类"宿主正常、容器为空"的故障变成一条命令可查。

**教训（与上一个缺陷同源）**：两次故障都不是"代码写错"，而是**验收方式没有覆盖真实链路**——
第一次是没跟随页面自身引用，这次是没验证容器内可见性。两者现在都有对应的门禁/自检脚本。

### 上线后第三个缺陷：深色主题下文字仍是黑色（2026-09-16）

**症状**：深色模式下正文是黑字，与深色背景几乎重叠；边框、悬停底色等也一起失效。
**根因**：`help.css` 直接引用了控制台的令牌名（`--ink`/`--page`/`--canvas`/`--line`/`--hover-2`…），
但共享的 `theme.css` **只定义了 `--docs-*` 与 `--scalar-*` 别名，从未定义这些裸令牌**
（其写法是 `--docs-ink: var(--ink, <回退值>)`，在文档站点上 `--ink` 本就未定义，只是靠回退值工作）。
于是 `color: var(--ink)` 属于 *invalid at computed-value time*：声明被整条丢弃，文字回落到初始值黑色。
**为什么之前没发现**：API 文档门户只用 `--docs-*`（自带回退值），恰好绕过了这个坑；帮助中心是第一个直接用裸令牌的站点。
**修复**：把 `theme.css` 从"别名层"升级为**令牌真源**——按 `console/src/styles/beautiful-ui.css` 的取值
在 `:root` / `.dark` 中真正定义 `--page/--canvas/--ink/--ink-2/--ink-3/--line/--line-strong/--line-soft/--hover/--hover-2/--field/--accent/--green/--orange/--red`，
`--docs-*` 退化为别名（数值一致，API 文档门户视觉不变，且 ink 取值顺带修正为与控制台一致）。
同时在 `tools` 侧新增**构建期门禁**：静态扫描 `theme.css` + `help.css`，任何以 `var(--x)`（无兜底）形式
引用却从未定义的变量都会让构建失败——用旧版 `theme.css` 试跑，门禁精准报出 8 个变量，与故障现象完全对应。

**三次缺陷的共同点**：都是"局部验证通过、链路没走通"。对应的三道防线现已固化：
① 链接/资源完整性门禁（跟随页面自身引用）；② 挂载自检（容器内可见性）；③ CSS 令牌完整性门禁（变量是否真的有定义）。

### 新增能力：浅色/深色主题切换（2026-09-16）

设计稿只写了"主题跟随控制台"，上线后按需求补上了**显式切换控件**，并且三个界面共用存储契约：

- 控件样式放在共享 `theme.css`（`.theme-toggle` 分段胶囊 + 滑动指示器 + `.theme-switching` 冻结过渡），
  帮助中心与 API 文档门户复用同一份，行为与控制台 `ThemeToggle` 对齐（无存储值时默认深色、写入 `bui-theme`、跨标签页同步）。
- API 文档门户额外通过 Scalar 实例的 `updateConfiguration({ …current, darkMode })` 同步渲染器，
  并设 `hideDarkModeToggle: true` 关掉 Scalar 自带的开关，避免同一页面两个主题控件各说各话。
- 控件默认 `hidden`，脚本接线后才显示，因此无 JavaScript 时不会留下一个点不动的按钮。
- 新增 `tools/test-theme-toggle.cjs`（jsdom）做**行为验证**：18 项断言覆盖类名翻转、持久化、
  aria 状态、指示器位移、重复点击幂等，以及 API 文档页的 Scalar 调用契约。
  首次运行时测试自身有两处假阳性（jsdom 未按真实顺序执行页面脚本、初始无 `dark` 类时点"浅色"是空操作），
  已修正测试而非放宽断言。
