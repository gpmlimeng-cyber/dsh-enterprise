# 配方 / Agent 预设 的 UI 需求条文（用户定位：开箱即用 · 零门槛 · 官方体系）

> 用户原话：「我希望把 Agent 预设做成**开箱即用**，**小白也能可视化配置的零门槛**，
> 同时 **UI 满足官方体系**」。本文把它落成可验收条文；实施任务书必须逐条引用并说明如何满足。

## 一、开箱即用（先给成品，不先给编辑器）

1. 员工侧提供**推荐配方画廊**（卡片式，按场景分类）；点一张 → **一步启用** → 立刻可用，全程**零配置**。
2. 创建侧提供**内置模板**（至少 4 套场景：代码评审 / 需求分析 / 文档写作 / 数据分析），
   模板本身即是"可直接发布"的成品，而不是空壳。
3. 任何入口都不允许出现"空白页等你自己填"的默认体验：没选模板时也要有推荐与示例。

## 二、三步可视化配置（不给 YAML）

- **第 1 步 · 身份**：名称（带示例占位）+ 一句话描述（带示例 + 长度提示）+ 分类（预置选项）。
- **第 2 步 · 组合**：模型（下拉）· 技能（可搜索的多选卡片）· 插件（开关列表，带一句话说明）·
  子智能体（数量/层级，给推荐值）· 规则（选内置规范包 **或** 粘贴文本）· 起始提示词（模板 + 填空）。
- **第 3 步 · 权限**：权限档位 · 允许的工具 · 是否需要联网（默认给"最保守但够用"的一档）。
- 每一步顶部有**一句话说明"这一步在做什么"**；不做多级嵌套弹窗；不做"必须先建技能才能建配方"的强制前置
  （缺前置时给"去创建"的入口，而不是死路）。

## 三、实时预览（边配边知道自己在造什么）

- 右侧常驻**实时摘要卡**：「这个智能体将会 —— 能做什么 / 需要什么 / 不能做什么」；
- 保存前必须能在摘要里看到：包含哪些技能与插件（含各自版本）· 权限档位 · 是否联网 · 需要哪些环境变量（只写名字）。
- 摘要卡在窄屏折叠到顶部，且始终可展开。

## 四、默认值即最佳实践

- 所有未填项落到**调研得出的推荐值**（模型档位 / 权限档位 / 是否联网 / 子智能体数量）——
  默认必须是"能跑起来且安全"，不是"空着等你填"。
- 任何默认值都要能在摘要里被看见（默认不等于隐形）。

## 五、高级模式是逃生门

- 底层组合（YAML）视图**默认收起**；展开后改动要有校验 + 预览 + 明确的"这会影响什么"提示。
- 小白路径永不依赖它；高级视图里的非法输入不能把小白路径带坏（fail-closed）。

## 六、可撤回

- 配置编辑支持**撤销/重做**；每次发布是一个**版本**，可回滚上一版。
- 删除/停用前提示**影响面**（几个分配、几台设备在用）。
- 与既有约定一致：错误就近显示 + 稳定错误码 + 可重试，绝不出现"点了没反应"。

## 七、官方 UI 体系（硬约束）

- 只用官方原语：`Switch` · `Tag`（tone 体系）· `StateDot` · `Modal` · `DisclosureRow`；
  若要用 `SegmentedTabs` 必须先确认工程 pin 与运行时一致（本会话已知 pin=0.1.5-rc.2 无它）。
- 颜色/字号/间距/圆角一律走官方 `--dsw-*` token；**不自创视觉、不硬编码色值**。
- 版式口径与「插件市场详情页」同源：分区标题 + 分区内容 + 发丝线。
- 无障碍：全程 tab 可达、焦点环可见、aria 正确；明暗主题与窄屏都成立。
- 每个元素都要能回答"官方的哪一个"（类名或 token 出处），写进实现的注释与汇报。

## 八、验收方式

- 机械可验（默认值落位 · 摘要内容 · 撤销重做 · 权限档位映射 · aria/键盘）→ **测试锁死**。
- 观感可验（三步流是否真"零门槛"、摘要卡是否一眼看懂、窄屏是否好用）→ **截图验收**：
  由用户看真机截图确认，不达标就改，不接受"设计如此"的解释。
