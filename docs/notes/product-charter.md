# 产品宪法：人人可用 · 极易上手 · 企业级 Agent 应用

> 用户原话：「我们的目标是把 dsh 打造成**人人可用**，**极易上手**的**企业级 Agent 应用**」。
> 本文是最高层取舍依据：任何功能、任何交互、任何文案，与本文冲突时以本文为准。

## 一、三根支柱

| 支柱 | 含义 | 可验收的表现 |
|---|---|---|
| **人人可用** | 非技术员工可用；不需要理解 YAML / CLI / 插件 / 技能 / 预设 / Cordis 等概念 | 界面文案里不出现这些词（见三）；新员工无需培训即可上手 |
| **极易上手** | 3 分钟内做出第一件有价值的事 | 首启有引导与示例；默认就绪；出错能自愈 |
| **企业级** | 可控、可审计、可治理、可撤回 | 管理员能看到并管住一切；员工侧不承担治理负担 |

**核心张力与解法**：「人人可用」与「企业级治理」冲突时 ——
**治理对管理员可见、对员工隐形**。员工侧只看到结果与「由企业统一管理」这类标记；
谁发的、装了什么、来源与许可、审计记录，全部在管理员那一侧。

## 二、三条操作律

1. **默认即最佳**：不填也能用，且默认是"能跑起来且安全"的那档；默认值必须可见（默认不等于隐形）。
2. **一步即达**：一步领用一个智能体 · 一步装上一个能力 · 一步问出第一个问题。
   主操作永不藏在折叠、二级页或"高级设置"里。
3. **失败自愈**：报错先给"我们帮你修好了"或一键修复；必须给稳定错误码时，
   也要配对一句人话与下一步动作，禁止把技术码直接砸给用户。

## 三、术语降维表（界面文案强制）

| 内部/技术说法 | 界面必须说 |
|---|---|
| preset / Cordis composition / bundle patch | **智能体**（或"预设的智能体"） |
| plugin | **能力**（必要时"插件能力"） |
| skill / SKILL.md | **技能**（必要时"专项技能"） |
| MCP / connector | **连接**（"连接到 XX 系统"） |
| manifest.json / .dshpreset / YAML | **不出现**；需要时表述为"配置文件（自动生成）" |
| 环境变量 / API Key | **凭据**（"需要配置 1 项凭据"）；键名只在管理员侧出现 |
| 分配 / assignment / subject_type | **可见范围** |
| 退休 / RETIRED | **下架** |
| PENDING_REVIEW | **待审核** |

## 四、验收口径

- **北极星**：新员工从打开应用到做出第一件有价值的事，**≤3 分钟、无需培训**。
- 过程指标：首次任务完成率 · 安装/启用成功率 · 报错自愈率 · 从"看到"到"用上"的点击次数。
- 每个功能切片在任务书里必须写明：它如何让上面某个指标变好；说不出来就是没想清楚。

## 五、反目标（明确不做）

- 不为了"功能多"牺牲上手成本；宁可少一个开关，也不多一步必须理解的配置。
- 不把治理机器暴露给员工（不出现"分配""审计""退休""权限码"这类词）。
- 不做只有专家能用的逃生门作为主路径（高级模式可以存在，但默认收起且非必需）。
- 不用技术术语做文案（含错误提示）。
- 不为了一次性方便而绕过既有治理（来源、许可、可撤回必须始终成立）。
