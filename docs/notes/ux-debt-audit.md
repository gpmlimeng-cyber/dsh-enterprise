# DSH Enterprise 体验审计（只读）· 体验债清单与修复方案

> 审计对象：Android 上的 DSH-ENT 仓库（`$R` = 本文件所在仓库根）。
> 本文件是**唯一产出**；未写任何源码/测试、未提交、未部署、未重启、未使用 `/tmp`。
> 人日口径沿用仓库既有约定（`docs/plan/skill-install-sources.md:878-879`）：1 人日 = 1 名熟悉本仓库的工程师有效工作 6 小时，含实现 + 测试 + 文档。

## 0. 一句话结论

**当前体验水平：骨架（结构、无障碍配对、原子落盘、不乐观撒谎）已经接近优秀，但「三态（加载/空/失败）+ 人话错误 + 大内容」这三块还是半成品**——最致命的是**失败永远只有一个 `ENT_*` 码**、**列表取数期间和失败后都是空白**、**183 文件的多层文件树不可折叠也不虚拟化**、**企业品牌会先渲染官方鱼标再切换成企业 logo**。

最该先修的三件事：

1. **错误可行动（③）**：给每个 `ENT_*` 配一句人话 + 就近就地显示 + 区分「可重试/不可重试」；并修掉**未进映射表的码落到 503**（`ENT_SKILL_ARCHIVE_INVALID` 等），以及**目录取数失败被 `.catch(()=>[])` 静默吞掉**。
2. **列表三态与零等待（①⑤）**：企业技能页签补加载态/空态/未登录态/失败态，禁止「空白 + 计数 0 跳 N」。
3. **大目录与大文件（⑥）**：文件树加折叠（目录可点）+ 大列表虚拟化；预览加截断/分页；对**必然失败的点击**（二进制、>256 KiB 文本）在树里就禁用并说明，而不是给一个永远失败的重试。

## 2. 按 12 条契约逐条打分

### ① 零等待感 —— **未达标**

- **反例（列表）**：企业技能页签**没有任何加载态**。`enterpriseSkills` 初值是 `[]`（`marketplace-entry.tsx:1924`），控制器里没有 `loading` 字段；渲染门控是 `skillsVisible = 技能组件开启 && rows.length > 0`（`:743`），而面板在门控不过时**整段渲染 `null`**（`:1837-1841`）。→ 首帧是**空白**，没有任何骨架/进度/内联提示。
- **反例（跳版）**：页签文案是「基础词 + 计数」（`:91-93`、`:762-767`），计数取「真正要渲染的行数」，取数期间为 `0`（`:750-754`）。→ 用户先看到「企业技能 **0**」，取数完成后跳成「企业技能 **11**」。
- **反例（N+1 与迟到标签）**：中心列表投影不带 `versionId`，控制器只对**已装行**逐个拉详情（`:1946-1948`），**全部** resolve 之后才 `setEnterpriseSkills`（`:1950`）。→ 行先渲染成「已装」，随后「有更新」药丸**插进来**，产生二次跳版。规划自己已把它列为 P0（`enterprise-marketplace-phase2.md:309` S6）。
- **反例（无超时）**：目录/已装清单取数只传 `controller.signal`，**没有 `AbortSignal.timeout`**（`:1937-1938`；对比同文件安装动作有 120s，`:2007`）。→ Host 挂住时页签**永久空白且永不失败**。
- **正例**：详情文件树/预览有四态五态纯投影（`:1398-1470`，含「正在读取文件列表…」`:1409`、「正在读取文件…」`:1446`）；安装/卸载在途有 `ongoing` 状态点 + 「安装中/卸载中」文案（`:520-538`）。

**缺口**：列表层完全没有等待语义；页面切换（进详情）与品牌首帧也没有。

### ② 零死按钮 —— **部分达标**

- **正例**：行本体在回调缺席时 `disabled` + `title='详情入口未接通'`（`:1725-1726`）；组件节节头缺席时 `disabled` + `title='折叠动作未接通'`（`:1227-1228`）；开关在无 store 时 `disabled` + `title='企业账号未登录，暂不可操作'`（`:1316-1319`）；插件行有 `installErrorCode` 时禁用并给 `title='该插件当前不可安装'`（`:1789-1791`）。
- **反例（真死按钮）**：安装/卸载动作有**单并发纪律**——`if (pendingSkill !== undefined) return`（`:2004`），但**只有 pending 那一行**的开关被禁用（`facts.busy` 只对命中行生效，`:1316`）。→ **A 行安装中时点 B 行的开关：完全没反应**，无 toast、无禁用、无 title。`skill-market.tsx:196` 是同一个写法。
- **反例（像坏的）**：未登录进「插件市场 → 企业技能」，页签显示「企业技能 0」、内容区**空白**，页面里没有任何「登录后可浏览」的说明；登录入口只藏在**另一个页签**（「组件」）的开关里（`:1256-1261`，`title='登录企业账号后启用'`）。

### ③ 错误可行动 —— **未达标（最严重）**

- **没有人话**：全仓**不存在**任何 `ENT_*` → 中文的映射表。唯一投影 `enterpriseLocalErrorCode` 只把错误对象取回原始码（`local-api-decode.ts:317-319`，非本地 API 错误统一 `ENT_LOCAL_UNAVAILABLE`）。UI 渲染形式恒为「动作前缀 + `<code>{码}</code>`」（`:1205`、`:1576-1578`、`:1637`、`:1670`；`skill-market.tsx:291`、`:348`）。测试把这个当预期：`tests/marketplace-entry.spec.ts:1272` 断言告警文本**包含** `ENT_SKILL_STATE_INVALID`。
- **稳定码不全在表里 → 掉 503**（核实结论：**真的**）：唯一映射表 `platform-client/src/local-api.ts:200-217` 只列了 12 个码（400/409/413/401/403/404/403），**其余一律 `return 503`**（`:216`）。技能安装链会掉进去的至少有：`ENT_SKILL_ARCHIVE_INVALID`、`ENT_SKILL_DOWNLOAD_FAILED`、`ENT_SKILL_SIZE_MISMATCH`、`ENT_SKILL_HASH_MISMATCH`、`ENT_SKILL_PACKAGE_MISMATCH`、`ENT_SKILL_STATE_INVALID`、`ENT_SKILL_INSTALL_FAILED`（码全集见 `bundle/src/skill-errors.ts:18-31`）。安装路由本身没有分支，直接吃这张表（`:613-644`，`:635-639`）→ **用户装到一个坏包/哈希不符，拿到的是「服务不可用 503」**。
  - 副作用比状态码更糟：503 语义是**可重试**，而这几个码里有 5 个是**同一包必然同错**的终态；`skill-route.ts:110-139` 还把该类型收窄成 `readonly status: 401 | 503`，编号语义被结构性地抹掉了。
  - 同一张表也管插件动作（`/plugins/{action}`），所以 `ENT_PLUGIN_HASH_MISMATCH`、`ENT_PLUGIN_ARTIFACT_INVALID`、`ENT_PLUGIN_INCOMPATIBLE` 等同样是 503。
- **静默**：目录取数失败 `.catch(() => [] as readonly EnterpriseRuntimeSkill[])`，已装清单失败同样（`:1936-1939`），最终 catch 也只是清空（`:1952-1956`）→ **登录失效/断网/中心 500 全都表现为「企业技能 0」+ 空白**，用户完全无从判断。对比设置页那份：`技能目录加载失败 <code>{errorCode}</code>`（`skill-market.tsx:255-256`）。
- **重试不可行动**：详情失败恒给「重试」按钮（`:1640-1646`、`:1673-1679`），但对**终态**错误（`ENT_SKILL_CONTENT_TOO_LARGE` 413 / `ENT_SKILL_CONTENT_INVALID` 409 / 深度超限 409）重试必然同错——规划明确要求区分（`skill-install-sources.md:861`）。
- **正例**：控制台 `_console.tsx:35-42` 的 errorComponent 是「暂时无法连接企业服务」+「重试」按钮；`403.tsx:33-40` 是「无控制台访问权限」+ 说明 + Sign out。**客户端插件的做法比控制台差**。

### ④ 一次点击即达 —— **部分达标**

- **正例**：安装/卸载开关常显在行上（`:1312`、`:1752`），不藏在折叠里；技能详情点行本体一次即达（`:1720-1727`）；「有更新」的更新动作也在行上（`:1297-1309`）。
- **反例**：**未登录时主操作（登录）不在默认页签**（见 ②）。用户第一眼落在「企业技能」空白页，必须自己发现「组件」页签才能登录。
- **反例**：「复制装配指令」在这条主路径上**没有**。它只在设置页「技能」tab 的详情弹窗里（`skill-market.tsx:323`、`:351-359`），而规划把它列为**必须保留的第二条路**（`add-skill-flow-reference.md:826-828`）。

### ⑤ 一眼可读 —— **部分达标**

- **正例**：状态点 + 状态词成对（`:520-538`、`:1252-1255`、`:1782-1785`）；标签短（版本短号 `:401-406`、分类签 `:416-419`、已装/未装 `:555-558`、「有更新」`:431`）。
- **反例（与用户口径正面相反）**：CSS 把**标题**设为让步方——`.own-market-cardHead{flex-wrap:nowrap; overflow:hidden}` + `.own-market-skillTitle{flex:0 1 auto; min-width:0}`（`:928-933`）而两枚签 `flex:none`（`:900`、`:904`），标题再套 `text-overflow:ellipsis`（`rowStyles` `:972`）。→ **标签把标题挤成省略号**。用户口径是「标题永不被挤掉」。缓解是版本签只显示短号（注释 `:931` 自己承认「这也是标签不再挤掉标题的前提」），窄屏 + 两签时仍会发生。
- **反例**：详情页标题不截断（`:1027`），但 `titleRow` 是 `flex-wrap:wrap`（`:1026`），版本 Tag 会**换行**，标题行高度不定。

### ⑥ 大内容不卡 —— **未达标**

真实规模（本机只读实测，`~/.sshwork/sh-probe/g1/skills`）：`canvas-design` **83 文件**、`claude-api` **81 文件 / 25 个目录**、`docx` **61 文件 / 最深相对目录层级 5**、`pptx` 56、`xlsx` 53。用户口径的 85–183 属同一量级。

- **无折叠**：目录行是 `<span>` **不是按钮**（`:1607-1611`，CSS 注释 `:1040-1041` 明说「目录行不是按钮」）→ 点了不会收拢；`enterpriseSkillTreeRows` 一次算全部行（`:1354-1368`），渲染是**一次铺满**（`:1598-1630`）。183 文件 = 183 个 `<li>` + 约 180 个 `<button>`，只靠 `max-height:360px; overflow:auto`（`:1037`）遮挡。
- **无虚拟化**：`plugin/packages/ui/package.json` 的依赖只有 `react`（peer）与 `dsh-client-ui-primitives`（dev），**没有任何虚拟化库**；源码里也没有窗口化实现。
- **层级只靠缩进**：单层 `<ul aria-label="技能文件树">`（`:1597`）+ 行内 `style={{paddingLeft: depth*14+'px'}}`（`:1605`）。没有 `role="tree"`/`treeitem`、没有 `aria-expanded`、没有 ↑/↓ 走焦；读屏只能听到一串扁平名字。
- **预览整篇进 DOM**：「长文件靠 `max-height` 滚动看全，**不做截断**」（CSS `:1054-1055`），`<pre>` 直接渲染全文（`:1662-1664`），解码上限 256 KiB（`skill-api-decode.ts:250-254`）。
- **必然失败的点击**：树里**每个文件都是可点按钮**（`:1613-1627`），但 Host 的文本读取会拒两类文件：>256 KiB → `ENT_SKILL_CONTENT_TOO_LARGE`（`skill-install.ts:715-716`、`:742`）；二进制/NUL/非法 UTF-8 → `ENT_SKILL_CONTENT_INVALID`（`:749-756`）。实测样本里 `canvas-design/canvas-fonts/*.ttf`（8 个二进制）与 `claude-api/shared/model-migration.md`（**309.5 KiB**，超上限）都是**必然点失败**的行，界面既不标注也不禁用。
- **上限是「全量失败」而不是「分页」**：`SKILL_FILE_MAX_ENTRIES = 1000`（`skill-install.ts:481`，超限 413 `:800-801`、`:853-855`）与 `SKILL_FILE_MAX_DEPTH = 8`（`:483`，超限 409 `:786-787`）。实测最深真实层级 5，**余量只有 3 层**，且一旦超限整棵树打不开（没有部分树/「继续加载」）。

### ⑦ 可撤回可重试 —— **部分达标**

- **正例（这部分是全仓最扎实的）**：安装是原子升级——下载到 `.part` + 强制 size/SHA-256 → 解包门禁 → 落点冲突预检 → 解到 staging → **旧目录先挪备份位、新目录再 rename**→ 状态文件原子写 → 清孤儿；任何中途失败**撤新目录 + 挪回旧目录**（`skill-install.ts:283-432`，回滚 `:420-424`）；状态文件同目录 tmp + rename（`:246-257`）。
- **正例（不乐观撒谎）**：成功后用 Host 返回的已装清单**覆盖**本地真值，失败把该行退回未装（`marketplace-entry.tsx:2010-2015`；`:1885` 注释「本页不做乐观切换」）；`installedSkillStatus` 还会校验每个技能目录是否真的还在盘上（`skill-install.ts:265-281`）。
- **反例**：**不可取消**。安装/卸载只有 120s 超时（`:2007`），UI 里没有取消入口（对比官方范式有 `cancelling` 阶段，`add-skill-flow-reference.md:471`、`:493-500`）。
- **反例**：**重试不分级**（见 ③）。

### ⑧ 信任可见 —— **未达标**

- **来源/许可/sha256 一条都看不到**：详情子页面只出「标题 + 版本 Tag + skillId + 描述 + 文件树」（`:1567-1574`、`:1581-1683`）；列表行只出「图标 + 标题 + 版本签 + 分类签 + 描述 + Switch」（`:1736-1752`）。没有许可、没有来源类型、没有 sha256。
- **sha256 就在手边却没用**：`EnterpriseInstalledSkill` 类型带 `sha256`（`skill-api-decode.ts:182`、`:217`），控制器把它作为 `installed` 传进了详情（`marketplace-entry.tsx:2144`）——**渲染一个字段就能显示**。中心侧那条线被解码层**主动丢弃**（`skill-api-decode.ts:25-26`、`:152`「sha256 只作形状门禁后丢弃」），所以「随手可查」现在只能走已装记录。
- **企业分发 vs 本机自装一眼可辨**：本机自装这条通路**还没实现**（规划 `skill-install-sources.md:671-691`、`:864-872`），因此当前只有企业分发一种行，这一条**无法判定为不达标，但也不成立**。
- **风险动作没有确认**：卸载是 `Switch` 直接 `onChange → onToggleSkill(row,false)`（`:1312-1320`），**无二次确认**；而它会删本机技能目录。
- **正例**：设置页那份技能详情有一段风险告知（「SKILL.md 正文是 Agent 会加载并执行的自然语言指令…『安装』只做下载、SHA-256 校验与落盘」`skill-market.tsx:302-305`）——**插件市场这条路径上没有这段话**。

## 3. 体验债清单（按优先级）

> 每条 = 现象 · 影响（用户视角一句话）· 证据 · 修复方案 · 工作量 · 风险

### P0（体验硬伤，用户第一眼就撞上）

#### P0-1 失败只有一个 `ENT_*` 码，没有人话
- **现象**：任何失败都渲染成「安装失败 `ENT_SKILL_STATE_INVALID`」「技能文件读取失败 `ENT_SKILL_CONTENT_TOO_LARGE`」。
- **影响**：「我知道出错了，但不知道我该干什么。」
- **证据**：`local-api-decode.ts:317-319`（无码→文案表）；`marketplace-entry.tsx:1205`、`:1576-1578`、`:1637`、`:1670`；`skill-market.tsx:291`、`:348`；测试反锁 `tests/marketplace-entry.spec.ts:1272`。
- **修复方案**：新增**唯一一份** `ENT_* → {人话, 可重试?}` 映射（放 `ui/src/local-api-decode.ts`，UI 与日志共用）；组件只渲染 `人话 + 稳定码（小字/悬浮）`；对「可重试=false」的码**不渲染重试按钮**，改为固定下一步（「换一个技能包 / 联系管理员」）。同时给 `skill-errors.ts:18-31` 的每个码补一条文案，缺文案时**兜底人话**（如「操作没能完成」）+ 码。
- **工作量**：2–3 人日（映射 + 两个界面的接线 + 用例）。
- **风险**：中。会碰到「界面只显示不自造文案」的既有规划口径（见 §4 C-3），需要先裁定；文本一旦上屏就涉及措辞评审。

#### P0-2 未进映射表的码落到 503（含 `ENT_SKILL_ARCHIVE_INVALID`）
- **现象**：坏包/哈希不符/大小不符/包契约不符/状态文件坏，全都被投影成 **HTTP 503**。
- **影响**：用户看到「服务不可用」，会去重试甚至报障；实际是**这份文件本身不行**，重试永远无效。
- **证据**：`platform-client/src/local-api.ts:200-217`（`:216 return 503` 是兜底）；码全集 `bundle/src/skill-errors.ts:18-31`；技能动作路由 `platform-client/src/local-api.ts:613-644`（`:635-639` 直接用这张表）；`bundle/src/skill-route.ts:110-139`（类型被收窄为 `401|503`）。
- **修复方案**：把 `ENT_SKILL_*` / `ENT_PLUGIN_*` 终态码显式入表——建议 `*_ARCHIVE_INVALID / *_PACKAGE_MISMATCH / *_ARTIFACT_INVALID → 422`（或统一 400）、`*_HASH_MISMATCH / *_SIZE_MISMATCH → 409`、`*_STATE_INVALID / *_INSTALL_FAILED → 500`、`*_DOWNLOAD_FAILED / ENT_PLATFORM_UNAVAILABLE → 503`（**只有这一对是可重试的 503**）；`skill-route.ts` 的 `SkillFailureProjection` 状态联合随之放宽。给这张表加一条「新增码必须入表」的用例（遍历 `EnterpriseSkillInstallErrorCode` 联合断言无码落 503）。
- **工作量**：0.5–1 人日（表 + 判别用例）。
- **风险**：低。唯一风险是既有测试对状态码的期望需要同步改（`platform-client/tests/local-api.spec.ts:32-38`）。

#### P0-3 列表取数失败被静默吞掉
- **现象**：会话过期/断网/中心故障 → 「企业技能 0」+ 全空白，没有任何提示。
- **影响**：「我们公司是不是没给我技能？」→ 用户不会报障，只会不用。
- **证据**：`marketplace-entry.tsx:1936-1939`（`.catch(() => [])`）、`:1952-1956`（`.catch` 只清空）、`:1837-1841`（门控不过渲染 null）；对照 `skill-market.tsx:255-256`。
- **修复方案**：控制器区分三态（`loading | ready | failed`），失败保留 `errorCode` 并**渲染在页签内容区**（人话 + 码 + 「重试」）；未登录单独一态给「登录企业账号后可浏览」+ 登录按钮（复用 `dialog.openDialog`）。**不要**再靠 `rows.length` 推断状态。
- **工作量**：1–1.5 人日。
- **风险**：低。会让「企业技能」tab 在未登录时也出现（现在是消失），需要产品确认这是期望行为（我认为是）。

#### P0-4 列表没有加载态，计数从 0 跳 N
- **现象**：进页面先看到空白页签 + 「0」，随后突然出现 N 行、「有更新」药丸再插进来。
- **影响**：「页面卡了一下」「数字还在变，是不是没加载完？」
- **证据**：`:1924`（`useState([])`）、`:1927-1958`（无 loading 字段、无 timeout）、`:743`、`:750-754`、`:766`、`:1946-1950`（N+1 后才 set）。
- **修复方案**：① 加 `loading` 首帧骨架（技能行占位，3 行即可）；② 页签计数在 loading 时**不显示数字**（或显示 `—`），避免 0→N；③ 给 `skills()/installedSkills()` 加 `AbortSignal.timeout(8_000)`（与 `skill-market.tsx:175` 同口径），超时进入失败态；④ 中期按规划 S6 让列表投影带 `versionId`，消掉 N+1 与迟到标签（`enterprise-marketplace-phase2.md:309`）。
- **工作量**：2–3 人日（①②③）；④ 另计（服务端 + 客户端解码，规划已列 P0）。
- **风险**：低。骨架样式需与官方 `StateDot/Shimmer` 口径对齐。

#### P0-5 文件树不可折叠、无虚拟化；大文件预览与必然失败的点击
- **现象**：83–183 个文件一次全铺出来，目录点不动收不拢；点二进制或 >256 KiB 文本必然报错；`<pre>` 一次渲染整篇 256 KiB。
- **影响**：多层技能「树」看起来像一大坨长列表，滚到怀疑人生；点字体文件报错会让人以为技能坏了。
- **证据**：`:1598-1630`（全量渲染）、`:1607-1611`（目录不是按钮）、`:1605`（只靠 `paddingLeft`）、`:1037`（`max-height:360px`）；`:1613-1627`（每个文件都可点）；`skill-install.ts:715-716`、`:749-756`（Host 必然拒 >256 KiB 与二进制）；实测样本 `canvas-design/canvas-fonts/*.ttf`、`claude-api/shared/model-migration.md`(309.5 KiB)；`:1662-1664` + CSS `:1054-1055`（预览不截断）。
- **修复方案**：
  1. 目录行改成真 `<button aria-expanded>`，树行加 `depth` → 折叠态集合（默认**只展开 SKILL.md 所在路径**），`role="tree"/treeitem"` + ↑/↓/←/→ 走焦；
  2. 行数 > 150 时只渲染可见窗口（自研简易窗口化，避免新依赖；或引入成熟虚拟化库，需评估 bundle 体积）；
  3. Host 在 `files` 投影里**加一个 `text: boolean`**（或让 `file` 路由 HEAD 一次），树里对二进制行**禁用**并标「二进制，不预览」；>256 KiB 的行标「过大（xxx KB），不预览」并禁用——**把必然失败变成可预期**；
  4. 预览超过 ~64 KiB 时只给前 N 行 + 「加载全文」按钮（明确告知体积）。
- **工作量**：3.5–5 人日（折叠/键盘/窗口化 2.5–3 + Host 加 `text` 标记 0.5 + 预览分页 0.5–1 + 用例 0.5）。
- **风险**：中高。窗口化是这一刀最容易引回归的地方（滚动位置、选中态、`data-*` 取证点都在测试里锁着）；`role="tree"` 会让现有「扁平 ul」的结构快照用例全部失败，需要同步基线化。

#### P0-6 品牌先渲染官方鱼标，再切换成企业 logo（闪烁）
- **现象**：冷启动/每次连接状态变化时，侧栏与「新会话」Hero **先出官方鱼标/官方字标**，企业品牌取数回来后才换成企业 logo/简称。
- **影响**：「刚才那个 logo 是谁？」——企业定制的第一印象被自己破坏。
- **证据**：座位注册由品牌视图驱动 —— 初始 `resolveEnterpriseBranding(null)`（`brand-occupants.tsx:147`），`custom=false` 时**撤掉注册**让官方接管（`:228-247`，注释 `:211-215` 说明为何不能用「返回 null」降级）；视图仅在 `store.api.branding()` resolve 后变化（`:162-170`）；每次 `platformUrl#state` 变化会**重新读一次**（`:172-178`）。同一份逻辑在 `useEnterpriseBranding`（`branding.ts:138-151`，初值 `null` → 内置 `DSHENT_ICON` `:84`、`:89`）。
- **修复方案**：① 把最后一次成功的品牌文档**缓存在本机**（`localStorage`/Host 侧小文件），首帧直接用缓存渲染企业品牌，取数只在**首帧之后**校正；② 加一个「品牌未就绪」的短窗口（例如 ≤400ms 内不换），避免肉眼可见切换；③ 或在 Host 侧把品牌注入到 boot 载荷（`window.__DSH_BOOT__`），彻底消除二次请求。**注意**：`bindEnterpriseBrandSeat` 的「先撤后注册」是官方 single 槽的硬约束，缓存方案不能破坏它。
- **工作量**：1.5–2.5 人日（缓存 + 首帧渲染 + 用例）。
- **风险**：中。缓存失效/换租户时要能正确丢弃；Host 侧注入方案会碰 `platform-client` 的装配载荷，范围更大。

#### P0-7 真实文件读不了：必然失败的点击仍可点、仍给「重试」
- **现象**：点 `.ttf`/`.xsd`/大 `.md` → 「技能文件读取失败 `ENT_SKILL_CONTENT_INVALID` / `ENT_SKILL_CONTENT_TOO_LARGE`」+ 一个**永远失败**的「重试」。
- **影响**：用户以为技能包损坏，反复点重试。
- **证据**：`skill-install.ts:715-716`、`:742`、`:749-756`；UI 恒给重试 `marketplace-entry.tsx:1640-1646`、`:1673-1679`；规划要求「校验/许可类失败不给重试」`skill-install-sources.md:861`。
- **修复方案**：合入 P0-5 第 3 条（树里禁用 + 标注），并把「不可重试」判定接到 P0-1 的映射表上；重试按钮只在 `可重试=true` 时渲染。
- **工作量**：1–1.5 人日（与 P0-5 有重叠，可合并计价）。
- **风险**：低。

### P1（显著影响，值得排在下一个迭代）

#### P1-8 主操作并发的静默 no-op
- **现象**：A 行安装中时点 B 行开关 → 毫无反应。
- **影响**：「这开关坏了？」
- **证据**：`:2004`（`if (pendingSkill !== undefined) return`）与 `:1316`（禁用只看本行 `facts.busy`）；`skill-market.tsx:196` 同。
- **修复方案**：把「有动作在途」提升为**全局**事实：非 pending 行的开关也 `disabled` + `title='另一个技能正在安装，请稍候'`；或允许排队（把一个动作入队并显示「已排队」）。至少**不能无声**。
- **工作量**：0.5–1 人日。
- **风险**：低。若选「全局禁用」，需确认不与「失败后可就地重试」冲突（失败后 pending 清空，仍可拨）。

#### P1-9 卸载无确认、动作不可取消、重试不分级
- **现象**：拨掉开关立即删本机技能目录，无二次确认；安装 2 分钟内不可取消。
- **影响**：误触即失去本机技能；长任务期间用户只能干等或强杀。
- **证据**：`:1312-1320`（无确认）；`:2007`（只有 120s 超时，无取消入口）；规划要求「校验/许可类失败不给重试」`skill-install-sources.md:861`、「上传/取包可取消」`:859`。
- **修复方案**：卸载加一个「人话确认」（「将从本机移除 skill-name，本机的技能文件会被删除；企业目录里的版本不受影响」）；进入 `pendingSkill` 后**至少**在同一行给「取消（停止等待）」= abort 本地等待并提示「无法确认是否已落盘，请刷新已装状态」（诚实措辞，不假装取消成功）。
- **工作量**：1–1.5 人日。
- **风险**：中。「取消」在原子落盘阶段**不应**宣称成功，需要按规划（`:824`）保持「不可取消阶段」的诚实语义。

#### P1-10 搜索缺失 + 同一目录两套界面
- **现象**：插件市场 →「企业技能」没有搜索框；设置页「技能」有。
- **影响**：技能多起来（规划口径里「商店」会有全量目录）就只能滚动找；两个入口能力不同让人怀疑自己看错了页面。
- **证据**：`:745-748`（注释承认搜索框随 store 外壳一起退场）；`:576`；对照 `skill-market.tsx:243-246`；规划要求「能搜」（`enterprise-marketplace-phase2.md:258`、S2 `:305`）。
- **修复方案**：把 `skill-market` 的工具栏（搜索 + 刷新）抽成共享子块，两处复用；搜索命中 `displayName/skillId/description/category`；空结果给「没有匹配的技能」+ 清空按钮。**不要再各写一份**。
- **工作量**：1–2 人日（抽共享子块 + 两处接线 + 用例）。
- **风险**：低。注意规划 §G.1 要求「从文件安装/从地址安装」也落在同一工具栏，抽块时要为它留位。

#### P1-11「有更新」迟到与 N+1
- **现象**：已装行的「有更新」药丸晚于行本体出现；每个已装行一次详情请求。
- **影响**：跳版 + 慢；已装行数增长后线性变慢。
- **证据**：`:1946-1950`；规划 S6 已把「列表投影补 `versionId`」列为 P0 并把 N+1 标为根因（`enterprise-marketplace-phase2.md:309`）。
- **修复方案**：按规划 S6 在 `RuntimeSummaryView` 补 `versionId` 并同步客户端解码，去掉详情轮询；过渡期把「有更新」的判定期做成骨架（占位不占行高）。
- **工作量**：服务端 + 解码 1–1.5 人日；过渡期 UI 0.3 人日。
- **风险**：低（规划已声明向后兼容）。

#### P1-12 详情无焦点管理 + 硬件返回键不回列表
- **现象**：进出详情后焦点丢到 `body`；Android 返回键直接离开插件页。
- **影响**：键盘/读屏用户每次都要从头 Tab；手机上「退不回去」，只能重新进入。
- **证据**：全文件仅 `:1131` 一处 `.focus()`；详情是纯视图状态（`:245`、`:1811-1814`、`:2157`）。
- **修复方案**：① 进详情时把焦点移到面包屑（或 `h3`，加 `tabIndex=-1`），返回时把焦点还给**原来那一行**（用包 id 找回 `[data-enterprise-skill-open=...]`）；② 用 `history.pushState` 把详情做成一条**可回退的历史项**（`popstate` → 回列表），不动官方路由体系也能让硬件返回键工作。
- **工作量**：1.5–2 人日（含窄屏/真机验证）。
- **风险**：中。动 `history` 可能与官方 page 视图的 tab/panel 机制打架，需要小范围可回退实现。

#### P1-13 企业分发行缺「来源 / 许可 / sha256」
- **现象**：详情与列表都看不到来源与许可；sha256 明明在数据里却不显示。
- **影响**：「这个技能谁发的？能不能信？」——用户无法自行核对。
- **证据**：`:1567-1574`、`:1736-1752`（渲染字段）；`skill-api-decode.ts:182`、`:217`（已装记录带 sha256）+ `marketplace-entry.tsx:2144`（已传进详情）；`:152`（中心侧 sha256 被丢弃）。
- **修复方案**：详情页加「信任区」：`来源：企业分发（管理员发布）`、`sha256: <前12位>`（取 `props.installed.sha256`；未装时显示「安装后可核对」）、`版本/发布时间`；把 `skill-market.tsx:302-305` 那段风险告知**抽成共享组件**，两条路径都挂上。
- **工作量**：1–1.5 人日。
- **风险**：低。仅「未装时看不到 sha256」需要产品认账（中心详情投影按现行策略不带 sha256）。
