## 附录：本会话学到的机理级教训（不是待办，是"别再踩"）

**① 「几何靠类名 + 样式表文档序」不安全** —— 官方主题 sheet 经 `ctx.effect` 追加进 `document.head`、
我们那份是 React 树里的 `<style>` ⇒ 先后不由我们决定 ⇒ 真机出现过"同一段文字先折三行、随后收成一行"。
处置：**必须成立的几何一律行内定死**（类名只管观感）；本仓已免疫 12 格。

**② 两份 `<style>` 都在 head 里，谁后谁赢** ⇒ 新加全局单类样式一律先问"撞不撞、谁赢"（同族先例：
官方 Menu 的 separator 用 l2，故我们的发丝线显式调 l1）。

**③ CSS 模板串里的反引号 = 提前闭合**（约 79KB 那一条）：一天之内绊倒三个人（两位代理 + 我本人）
⇒ 规矩：该区间反引号计数必须为 0，改完自查。

**④ 「检测到(present)」与「有技能(count)」是两把独立尺子** —— 别靠推断让一把顶替另一把。

**⑤ 假绿三种形态都要防**：只验构造器不验调用点 / 定时器推到截止后数（已触发消失）/ 匹配串写错导致
文件根本没被改却只 grep 了"测试通过"。⇒ 每刀红→绿必须**按 md5 逐字节还原**。
