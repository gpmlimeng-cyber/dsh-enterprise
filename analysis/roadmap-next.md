## 1.5 两条机理级教训（写在这里，免得下次重踩）

**① 「几何靠类名 + 样式表文档序」是不安全的 —— 这条坑真机可见过一次**
```
症状：同一张卡、同一处文字，首帧折三行、随后收成一行（用户原话）。
根因（已坐实）：官方主题 sheet 是**插件激活那一刻**经 ctx.effect 追加进 document.head 的
   （dsh-client-ui-theme/lib/client.js:1180-1193 installThemeStyles）；而我们那份 esc 样式是
   **React 树里的 <style>**（esc-style.ts:1518，挂在 esc-page.tsx:255）⇒ **两份的先后不由我们定**。
   官方 sheet 晚到 ⇒ 文档序上压在我们之后 ⇒ 我们的 .esc-card-headdesc(nowrap) 那一刻不生效
   ⇒ 按默认 normal 自由折行；它到位后覆盖回来 ⇒ 收成一行。
处置：**必须成立的几何一律行内定死**（行内样式永远压任何 stylesheet，除 !important —— 官方三个 UI 包零出现）；
   类名只承担观感，不承担"不能破的约束"。CSS 原规则保留（免疫 ≠ 拆样式）。
原则：以后凡新加"单行截断 / 定高 / 不换行"这类**约束性**几何，先问一句：这条是靠类名还是行内？
待办：同类风险格子清单（元信息行 / 标签行 / 工具栏药丸 / 分类 chip / 技能名标题 / 搜索框 / 二级 chip …）——
   只列不改，按严重度单独派刀。
```

**② 两份 `<style>` 都在 head 里，谁后谁赢**
⇒ 我们新加的全局单类 `<style>` 一律要问"与官方那份撞不撞、撞了谁赢"；能行内就别赌顺序。
（同族先例：官方 `Menu.module.css` 的 separator 用 l2，所以我们的发丝线**显式**调到 l1 —— 那也是"不赌顺序"。）

## 1.7 又两条（本轮新增，都是"差点变成假绿"的东西）

**① CSS 模板串里的反引号 —— 一天之内绊倒三个人（含我）**
```
esc-style.ts 的 CSS 是一整条模板串（约 79 KB）：**串内任何反引号都会把它提前闭合** ⇒ tsc 报 TS1005。
  今天三位写者各栽一次：写注释时用反引号包类名（`.esc-third-party-head`）、我在 python 里用 ASCII 引号包中文、
  注释里 `margin-top` 那种行内代码。⇒ 规矩：**这段模板串内反引号计数必须为 0**，改完自查（已验证的读法：
  取 `const CSS = \`` 到下一个反引号的区间、数里面的反引号，必须是 0）。
```

**② 「两把尺子不许互相顶替」——`present` 与 `count` 是独立的两件事**
```
本地三方那一维的可见判据是三句：有技能（count>0）+ 不是别名（aliasOf 未定义）+ **检测到（present===true）**。
第一版实现把「检测到」当成 count>0 的顺带覆盖，并在注释里断言"解码层保证未检测到的根必然 count:0"——
查证 skill-api-decode.ts：**这个耦合不存在**（present 只校验是布尔、count 只校验与候选条数相等，互不相关）
⇒ `present:false && count:3` 会原样通过解码，界面会报一个**位置根本不存在**的来源。
真机取证（本轮实测）：25 个根里该形状 **0 枚** ⇒ 第三字段是**防御性**的（但留着 —— 靠推断省掉一把尺子
正是这一类 bug 的来源）。判据收成唯一一枚 `enterpriseThirdPartyRootVisible`，chip/可见来源/组标题三处共用。
```

## 1.8 用户新裁决：「全部」那一行标签**整体右移**，胶囊与卡片**左对齐**

```
现状（刻意立过的口径）：.esc-category-tabs 带负外边距 `margin-left: calc(0px - var(--esc-cat-pad))`（−12px），
  用来吃掉**首枚胶囊自己的左内衬** ⇒ 结果是**首枚的文字**与卡片左边界（.esc-content 的 24px）对齐。
用户要：**胶囊的框**与卡片左边界对齐 ⇒ 去掉那条负外边距（整行右移 12px）。
范围（我的口径）：**只改这一行**（`.esc-category-tabs` = 二级 chip 行，含「全部」）。
  ★同一手法还有两处（三页签 `.esc-resource-tab` 一族与维度页签 `.esc-source-tabs`，用的是 `--esc-tab-px`）
    ⇒ **不擅自一起改**：交付里登记"它们同族、未动"，由用户再裁（要一致就一起改）。
判据（源码级，vitest 无布局引擎）：那一行**不许**再带负左外边距；容器左内衬与卡片左边界同源；
  并写清"框对齐"取代"文字对齐"的理由（用户原话）。
```

## 7. 运维 / 流程（我这一侧的纪律，写下来免得忘）

```
· 派刀前：git fetch + 复测基线（远端不可达时以本地 HEAD 为基线并记下）
· 每刀回来：自己复跑门禁 + 抽查它自报的 md5 + 逐条核关键不变量（不信报告）
· 提交/打包：**挂在测试退出码上**（红了就停）—— 除"纯文档"提交外，没有例外
· 同包不并行：一刀一包；跨包并行只在不同包之间
· 打包装机：一次重启尽量多带几刀；每次留回滚包 + 记 sha256
· 子任务模型：默认 workbuddy/space-bunny（机械 medium · 收尾 high · 硬骨头 xhigh~max）
· 真机读数：一律用 curl 逐条计时/逐条比对，不靠推测；"我没验"要如实写进交付
```
